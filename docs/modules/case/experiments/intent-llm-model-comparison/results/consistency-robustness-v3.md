# 반복 일관성 · 단일 점수 — robustness-v3(100케이스)

**날짜:** 2026-10-05 · **작성:** 유소연(case) · **계기:** 멘토 피드백 Q2 · #213 메인 리뷰
- Q2: 「테스트 케이스가 48건이라면 더 늘려도 좋겠다. 좋은 모델에게 데이터 증강을 요청할 수 있다(지식 증류). 비결정적인 모델은 같은 요청을 여러 번 해 일관적인지 확인하는 평가도 필요하다.」
- #213: 「각 테스트케이스를 5회 정도 반복해 일관성을 수치화하고, 정확도를 더해 하나의 점수로 만들어 그 점수로 판단하라.」

**원본:** 모델 출력 · 규칙 판정 · judge 판정 JSON(`predictions-v3-consistency/`, 2,075개)은 레포에 두지 않는다(멘토 리뷰 #146). **판단 기준(측정 전에 등재):** `decisions/intent-llm-eval-target-thresholds.md` §1.0 — 단일 점수 = 평균 필드 정확도 × 필드 일관성, 통과 조건 hallucination ≤5%.

- 두 모델 모두 hallucination 통과 조건을 넘었다. Flash-Lite는 robustness-v2(v1 프롬프트)의 8%에서 2.4%로 내려왔다 — v3 프롬프트 효과와 데이터셋 차이가 섞여 있어 둘을 나눠 말할 수는 없다.
- 필드 일관성(글자 비교)은 뜻이 같고 표현만 다른 출력(「빨간불에 지나감」 · 「신호위반」)도 흔들림으로 센다. 그래서 「5회 출력이 글자까지 같은 케이스」는 59 · 40으로 낮다. 판정이 5회 내내 같은지(판정 일관성)로 보면 두 모델 다 98% 이상이다 — **표현은 흔들려도 맞고 틀림은 거의 흔들리지 않는다.**
- 3.8 Flash는 500회 중 1회 출력 길이 한도에 걸려 실패했다(내부 추론 토큰 1,917개, 한도 2,000 — `v3-multi-event-03` r1). 같은 입력으로 한 번 더 불러 대체했다. 운영 경로에서도 생길 수 있는 실패라 Search public 함수의 출력 한도 · 재시도에 반영할 일이다(#210).

- 두 모델이 갈리는 곳은 **모호 · 모순 · 인젝션**이다. Flash-Lite는 흐린 진술을 구체 값으로 채우거나 confidence를 high로 두는 경우가 더 많다.
- **`correction_target_오염_시도`가 98%다.** robustness-v2(v1 프롬프트)에서 4개 모델 모두 47~67%였던 약점이, v3 프롬프트(무관 사실 무시 · low + 명시적 전환 예외, Q3 실험)로 두 모델 다 해결됐다.
- `모순_정보`가 3.8 Flash도 83%로 가장 낮다 — 앞 값을 함께 담거나 confidence를 high로 두는 경우다. 정책(마지막 값 + low)을 프롬프트에 명시할지 검토할 일이다.

## 2. 데이터셋 — robustness-v3(100케이스)

- **만든 방법(지식 증류):** 기존 55건(eval-v1 7 + robustness-v2 48)을 seed로 Claude Opus 5.5(Claude Code)가 teacher가 되어 생성. robustness 10개 카테고리 × 8 + 정상 계열 7개 카테고리 20. 생성 규칙은 `datasets/intent-hint-robustness-v3.SPEC.md`, 개념은 `research/knowledge-distillation-data-augmentation.md`.
- **규칙 채점용 구조화 정답:** 행마다 `expected` — 필드별 `null`(값이 없어야 함) · `null_or_vague`(없거나 식별 불가) · `any_of`(들어 있으면 정답인 핵심어) · `none_of`(들어가면 오답인 말), 행 단위 `none_of_all_hints`(어느 칸에도 금지), 여러 사건은 사건별 `events`(출력 필드가 한 사건에 속해야 함 — 사건 교차 조합은 오답).
- **검증:**
  - 자동 필터 — id 중복 · seed 존재 · 카테고리 일치 · 형식 · seed와의 유사도 · `any_of`와 금지어 충돌. 걸린 것은 빈 문자열 1건(seed와 같은 빈 입력, 의도된 중복).
  - **독립 재라벨** — 다른 teacher 인스턴스 2개가 정답을 가린 문장만 보고 정답을 다시 썼다. 100건 중 99건 일치.
  - **사람 확인 — 일괄 승인.** 불일치 1건 + 재라벨러가 애매하다고 짚은 8건 + 무작위 20건(겹침 제외 27건)을 확인 페이지로 준비했고, 유소연이 훑어본 뒤 **행별 검토 없이 일괄 승인**했다. 판단이 갈리는 4건은 추천안으로 정했다(아래).
- **사람 확인에서 정한 것:**
  1. 여러 사건이 섞인 발화는 confidence **low만 정답** — seed(case-09a)는 「한 사건만 + high」도 정답으로 봤지만, 사건이 섞이면 다시 적어 달라는 안내(#266)가 필요한 경우라 low로 고정.
  2. 「어제였나 그저께였나」는 `null_or_vague`(v3-new-incident-07).
  3. 정정 + 같은 사건의 모호한 덧말은 지금 정답대로(모호 필드는 null/모호, `correction_target`은 분명한 쪽, low).
  4. 잡담 속 지명(「상무지구 국밥집」)은 전부 null.
- **seed끼리 다른 기준 하나:** case-02(일부 누락)는 「필드가 빠져도 진술이 분명하면 high」, case-12b(인젝션)는 「시간 · 위치가 없으니 high면 오답」이다. v3는 v3 프롬프트 정의(「진술이 분명한 정도」)를 따라 case-02 쪽으로 정답을 썼다. 기존 파일은 locked라 고치지 않았다.

## 3. 방법

- 후보 2개 × 100케이스 × **5회**, 프롬프트 **v3**(`schema.py` `CANDIDATE_SYSTEM_PROMPT_V3` — 운영에 넣을 방향, #210). 하네스 `scripts/consistency_eval.py`(`run` · `rule-score` · `judge` · `summarize`).
- **규칙 채점 우선:** `correction_target` · `confidence`는 값 비교, 4개 hint는 위 구조화 정답으로 판정(소문자 · 공백 · 문장부호 제거 뒤 비교). 판정 6,000개 중 **105개(1.75%)** 만 규칙으로 정하지 못했다.
- **judge는 그 105개가 있는 출력 75개만, 같은 케이스에서 출력이 같으면 한 번만** 보냈다 — Sonnet 5 호출 32건, 나머지 43건은 판정 재사용. judge는 보강 판정 기준의 Claude Sonnet 5(`judge-validation-robustness-v2.md` §「judge 운영」), run_id `20261005T-v3-sonnet5`.
- 일관성은 judge 없이 출력끼리 비교했다.

## 4. 비용 — 지원금 사정과 Sonnet 5 선택

**배경:** 2026-10-05 기준 Elice 지원금의 67%를 이미 썼다(search와 공유). 처음 설계(후보 4개 × 150케이스 × 5회, 모든 출력을 judge)는 ₩30,000~55,000으로 추정돼 접었다.

**줄인 방법:**

| 항목 | 처음 설계 | 실제 |
| --- | --- | --- |
| 데이터 생성 | Elice Opus 5 | **Claude Code(Opus 5.5) — 지원금 ₩0** |
| 후보 | 4개 | **2개** — GPT-5 Nano(정확도 최하 · latency 16.9초 · 출력 한도 문제), Claude Haiku 4.5(비용 최고 · Q3에서 v3 프롬프트로도 오염 6/10)는 이전 실측으로 이미 처져 제외 |
| 케이스 | 150 | 100 |
| 채점 | 출력 전부 judge(판정 약 3,000건) | **규칙 우선 + 남은 것만 judge, 중복 출력 재사용 — 32건** |
| 일관성 | — | judge 없이 출력 비교 — ₩0 |

**judge를 Sonnet 5로 한 이유:** 규칙으로 못 정한 판정을 Claude Code 세션에서 하면 지원금 ₩0이지만, 지금까지의 모든 숫자(robustness-v2 · judge 신뢰도 검증 · Q3)가 보강 기준 Sonnet 5로 채점됐다. 같은 judge를 써야 이전 결과와 비교할 수 있고 judge 신뢰도 검증 결과(사람 판정 일치 등)도 그대로 적용된다. 그래서 공식 채점은 Sonnet 5로 하되, 호출 수를 규칙 채점 · 중복 재사용으로 줄였다(유소연 결정, 2026-10-05).

**실제 비용(Elice):**

| 항목 | 호출 | 비용 |
| --- | --- | --- |
| Gemini 3.8 Flash | 500 + 실패 1 + 사전 확인 2 | ₩1,514 + 약 ₩12 + 약 ₩5 |
| Gemini 3.1 Flash-Lite | 500 + 사전 확인 2 | ₩224 + 약 ₩1 |
| judge Sonnet 5 | 32 | ₩566 |
| **합계** | | **약 ₩2,320** |

처음 추정의 4~8% 수준이다. 3.8 Flash 단가(입력 ₩1,141 · 출력 ₩5,709 / 1M 토큰)는 2026-10-05 Elice 모델 카드에서 확인해 `scripts/pricing.py`에 넣었다. 호출당 3.8 Flash 약 ₩3.0, Flash-Lite 약 ₩0.45 — **3.8 Flash가 약 6.8배**다. 출력 토큰이 약 4배 많다(내부 추론 · `reasoning` 필드).

## 5. 한계

- **순환:** teacher(Claude Opus 5.5) · 재라벨러(같은 모델) · judge(Claude Sonnet 5)가 모두 Claude 계열이다. 재라벨 99% 일치는 독립성이 약한 만큼 낮춰 읽어야 하고, 사람 확인은 일괄 승인이라 이 순환을 사람이 끊지 못했다. 후보(Gemini)와 teacher는 다른 계열이라 「teacher가 특정 후보에 유리하다」는 위험은 작다.
- **합성 데이터:** 실사용자 문장이 아니다. 정확도가 robustness-v2보다 높게(3.8 Flash 93% → 97%) 나온 데는 teacher가 쓴 문장이 더 깔끔한 영향도 있을 수 있다. 실사용 로그 평가는 여전히 미결(`research/llm-model-comparison-hint-extraction.md`).
- **후보 2개:** Nano · Haiku는 이번 5회 반복에 넣지 않았다(위 비용 표의 근거).
- **글자 비교 일관성:** 자유 텍스트 필드라 실제보다 낮게 잰다(보조 지표 판정 일관성 참고). 단일 점수는 등재한 정의(글자 비교) 그대로 계산했다.
- **규칙 채점:** 핵심어가 들어 있으면 정답으로 본다 — 핵심어는 맞지만 문장 전체가 엉뚱한 출력은 놓칠 수 있다. 금지어(`none_of`)가 그 일부를 막는다.
