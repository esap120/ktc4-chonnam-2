**날짜:** 2026-10-05 · **작성:** 유소연(case) · **계기:** 멘토 피드백 Q2 — 「테스트 케이스가 48건이라면 더 늘려도 좋겠다. 좋은 모델에게 데이터 증강을 요청할 수 있다. 지식 증류의 개념인데 가볍게 공부해 보면 좋겠다.」
**적용:** `experiments/intent-llm-model-comparison/results/consistency-robustness-v3.md`(robustness-v3 데이터셋 생성)

## 1. 지식 증류(knowledge distillation)란

크고 강한 모델(**teacher**)이 가진 지식을 작은 모델(**student**)에게 옮기는 방법이다. 원래 형태(Hinton 외, 2015)는 teacher의 출력 확률 분포(soft label)를 student가 따라 배우게 하는 학습 기법이다. 정답 하나(hard label)보다 「틀린 답들 사이의 상대적인 그럴듯함」까지 전달돼 student가 더 잘 일반화한다.

LLM 시대에는 뜻이 넓어졌다. teacher LLM이 **데이터 자체를 만들어** student 학습이나 평가에 쓰는 것도 증류라고 부른다.

| 형태 | teacher가 주는 것 | 예 |
| --- | --- | --- |
| 출력 분포 증류 | 토큰별 확률(soft label) | 원래 의미의 KD |
| 응답 증류 | 문제에 대한 답 · 풀이 | 강한 모델의 답으로 작은 모델 fine-tuning |
| **데이터 증강(합성 데이터)** | **새 입력 + 정답 라벨** | 이번 작업 — 평가용 케이스를 늘림 |

이번 작업은 학습이 아니라 **평가 데이터**를 만드는 데 teacher를 썼다. student(평가받는 모델)를 바꾸지 않고, teacher가 만든 문제로 student들을 시험한다.

## 2. 합성 데이터의 위험과 이번 대응

합성 데이터는 싸고 빠르지만, 세 가지 위험이 알려져 있다.

| 위험 | 무엇이 문제인가 | 이번 대응 |
| --- | --- | --- |
| **분포 편향** | teacher가 쓰는 문장은 teacher의 말투 · 어휘로 쏠린다. 실사용자 문장과 다르다 | seed(사람이 쓴 55건)의 함정을 유지하고 표현 · 지명 · 차량 · 위반을 바꾸게 했다. **그래도 실사용 문장이 아니라는 한계는 남는다** — 실사용 로그 평가는 미결 |
| **teacher 오류 전파** | teacher가 정답을 틀리게 쓰면 그대로 「정답」이 된다 | 정답을 다른 teacher 인스턴스가 문장만 보고 **독립적으로 다시 쓰게** 해, 둘이 다르면 사람이 확인했다. 나머지에서도 무작위 20%를 사람이 봤다 |
| **평가 순환(contamination)** | 데이터를 만든 모델 계열이 채점도 하면, 자기 기준에 맞는 답에 점수를 준다. 평가받는 후보와 teacher가 같은 계열이면 그 후보에 유리하다 | teacher를 **후보가 아닌 모델**(Claude Opus 5.5)로 골랐다. 채점은 규칙 우선이고 judge(Claude Sonnet 5)는 규칙으로 못 정한 것만 본다. teacher와 judge가 같은 Claude 계열이라는 순환은 사람 확인으로 줄일 뿐 없애지는 못했다 |

## 3. 왜 이번엔 Elice가 아니라 Claude Code였나

teacher 호출을 Elice ML API로 하면 지원금 크레딧을 쓴다. 지원금의 67%를 이미 써서(2026-10-05), 데이터 생성은 Claude Code 세션(Opus 5.5)에서 했다 — 지원금 비용 0. 증류의 조건(「후보보다 강한 모델이 만든다」)은 그대로 성립한다.
