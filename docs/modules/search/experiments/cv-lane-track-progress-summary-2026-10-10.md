# CV_LANE_TRACK v1 — 진행 결과와 남은 작업

## 1. 현재 결론

**최신 잔여 작업 처리:** [완료한 구현·검증과 남은3묶음](cv-remaining-plan-2026-10-11.md). 차량 평가·선정, 검출 모델별 추적 비교·평가, 차선 평가 실행기를 구현했다. 원본5fps549프레임의 V1/V4×두 추적기 진단과 L1 중복 처리 후 전체3,233프레임 비교를 완료했다. youtube약1.789초 후보를 새로 복구했지만 L1 전체 교체는 보류해 채택 기준은 후보11개·시간대5/11이다. 실제 GT 점수·모델 선정·위반 유형·정식 규칙 비교는 미완료다. 남은 범위는 정답·정상 영상 확보, L2 환경 해결, 이후 최종 선정·판정·검증의3묶음이며 추가 누락 진단을 새 필수 작업으로 늘리지 않는다.

**모델을 실행해 속도와 출력 형태를 비교하고, 차량 추적과 차선 교차 후보 생성까지 연결했다. 정확도가 가장 좋은 모델과 최종 조합은 아직 선정하지 않았다.** 차량·차선·추적 정답 라벨(GT)이 없으므로 현재 수치만으로 검출 정확도, 사건 재현율, 실제 오탐률을 판단할 수 없다.

현재 연결한 조합은 **V1 AI Hub YOLOv5 차량 검출 + L3 UFLDv2 차선 검출 + ByteTrack/BoT-SORT 추적**이다. 실행 가능한 모델의 속도와 출력 관찰을 근거로 선택한 임시 조합이다. 차량 모델은 차량 위치를 찾고, 별도의 차선 모델이 차선 곡선을 찾는다. 추적기는 프레임 사이 같은 차량을 연결한다.

안정화 v2에서는 교차 후보가 **5건 → 2건**으로 줄었다. 남은 2건은 **C00 영상의 같은 시점 약 13.50초를 두 추적기가 각각 잡은 것**으로, 화면상 구간은 하나다. 후보는 모두 `UNKNOWN`이며 실선 차선 변경·중앙선 침범 등 실제 위반으로 확정한 결과는 없다. 보정 성공은 늘었지만 차선 연결은 줄어, 이번 변경을 종합적인 정확도·안정성 개선으로 채택하지 않았다.

**후속 1번 작업 완료:** [보정 선택과 차선 연결 개선](cv-crossing-continuity-2026-10-10.md)에서 유사 변환 우선·full 보완을 구현·검증했다. 보정 실패763→656, 연결 차선5,058→5,366, 새 차선ID2,687→2,379이며 C00 두 후보는 유지됐다. 입력 차선 오류와 정확도 미평가 상태는 남아 있다.

**2번 좌표 정리·기존 사건 시간대 대조 완료:** [평가 라벨 준비](cv-label-preparation-2026-10-10.md)의 1,200장·29작업을 평가용 파일로 정리하고, 사용자의 차선 육안 검수 통과를 기록했다. [시간대 대조 결과](cv-evaluation-preparation-2026-10-10.md)는 기존 정답11구간 중 C00 한 구간에만 현재 후보가 있음을 보여준다. 기존 사건·시작 시각은 재사용하며 반복 입력을 요구하지 않는다. 프레임별 좌표·대상 ID 검증과 정량 정확도 평가는 별도 상태다.

**후속 누락 진단·C09 상태 오류 수정 완료(2026-10-11):** [누락 원인과 수정 결과](cv-missed-crossing-diagnosis-2026-10-11.md). 연속 중립 관측을 오래된 관측으로 잘못 처리하던 분기를 제거했다. 동일15개 영상에서 후보2→4, 후보가 포함된 정답 시간대1/11→2/11(C00·C09)이며 기존 C00 후보는 정확히 유지됐다. 남은9구간은 작은 차량 보류와 대상·차선 연결 등을 추가 진단해야 한다. 아래 v2 수치는 당시 기준 결과이며 사건 정확도 수치가 아니다.

## 2. 단계별 완료 상태

**L1 대체 차선 전체 비교 완료(2026-10-11):** [전체 입력·교차·원시 마스크 비교](cv-l1-crossing-support-2026-10-11.md). 대체 차선 입력을 명시적으로 선택할 수 있게 연결하고 같은15영상3,233프레임을 두 추적기로 비교했다. L1 후보9개·정답 시간대 포함1/11이며 남은6구간 복구는0개다. 차선 중복과 횡단보도·차량 주변의 잘못된 마스크를 확인해 전체 교체는 채택하지 않았다. 기존 L3 결과는 프레임·후보 모두 정확히 유지됐고, 최신 후보11개·시간대5/11·미복구6구간이 현재 개발 기준이다.91테스트·60출력영상·21시트 검증을 마쳤으며 대상·차선 ID가 포함된 사건 정확도는 미평가다.

**오토바이 전용 입력 연결 완료(2026-10-11):** [M1 몸체 검출·추적·교차 실행](cv-motorcycle-support-2026-10-11.md). 기존 V1에 없는 오토바이 몸체 클래스만 별도 연결하고 최신 V1 차선·보정을 정확히 재사용했다. 전체3,233프레임·60영상·81테스트를 검증했다. L3의 adapter p50은 L1의 두 모델 결합보다 약 **3.8배 빨랐다.** 전처리와 출력 구조가 다르므로 모델 자체 연산량의 공정한 비교나 정확도 우월성으로 확대 해석하지 않는다. L2는 소스·가중치를 확보했지만 CUDA 컴파일러 부재와 Docker 시작 실패로 막혔다. 성능이 낮아서 탈락한 모델이 아니다.

빈 차선 출력은 L1 1/1,200, L3 96/1,200이었다. 정답이 없고 출력 단위도 다르므로 이 숫자는 차선 누락률·recall이 아니다.

**L3는 차선 위치 곡선만 제공한다.** 현재 출력에는 신뢰도, 백색·황색, 실선·점선, 중앙선 역할이 없다. 신뢰도는 `null`, 의미는 `UNKNOWN`으로 저장하며 시각화 색상은 선을 구분하는 표시다. 최종 모델 선정과 차선 유형 판별은 남아 있다.

## 5. 차량 추적과 최초 교차 후보

V1·L3로 전체 15개 영상을 한 번 처리하고, 같은 V1 검출 캐시를 두 추적기에 입력했다. 신뢰도 임계값 0.25는 GT로 보정한 값이 아니다. BoT-SORT는 ReID를 끄고 sparse optical flow 기반 카메라 보정을 사용했다.

| 추적기 | 추적 단계 p50 / p95(ms/프레임) | 출력 관측 수 | 영상별 차량 ID 수의 합 |
| --- | ---: | ---: | ---: |
| ByteTrack | 1.96 / 3.34 | 16,558 | 595 |
| BoT-SORT | 8.14 / 25.68 | 16,693 | 682 |

ByteTrack이 이 설정에서 더 빨랐다. 관측 수·ID 개수·관측 간격은 진단 수치이며 실제 ID 전환 횟수나 추적 정확도를 뜻하지 않는다. 육안으로는 V1의 중복 bbox, 보행자를 차량으로 잡은 사례, 흐린 장면의 차량 관측 공백과 L3의 잘못된 곡선을 확인했다.

최초 교차 단계는 **현재 검출 bbox의 아래쪽 중앙점을 차량 접지의 대리점**으로 사용했다. 이 점과 같은 높이의 차선 사이 거리 부호가 바뀌고 일정 시간 유지되면 후보를 만들었다. 실제 타이어 접지는 라벨링하지 않았고, 추적기의 예측 bbox만 남은 프레임은 접지 관측으로 사용하지 않았다.

최초 결과는 ByteTrack 2건·BoT-SORT 3건, 총 5건으로 화면상 C00·C33·C10의 3개 구간이었다. 두 추적기가 같은 사건을 잡으면 각각의 진단 후보로 남기므로 후보 개수와 실제 사건 개수는 다르다. 차선 신뢰도·유형이 없어 점수와 위반 유형을 만들지 않았고 Top-K 순위도 매기지 않았다.

현재 개발 사건은 **차선 관련 11건(실선 변경9건·중앙선2건, 선 색상은 추가 검수 필요)**이며 신호위반 2건은 이 평가 분모에서 제외한다. 기준 설정 후보4건이나 원거리 실험 후보7건을11건과 단순히 나눠 recall로 계산할 수 없다. 사건 대상 차량과 실제 교차를 맞췄는지 확인해야 한다.

조건을 확정한 뒤 정상·독립 검증 데이터를 평가해야 한다. 모든 15개 개발 영상과 후속 예측을 이미 관찰했으므로 지금 만드는 GT를 과거의 ‘예측을 보기 전에 작성한 독립 GT’라고 기록할 수 없다.

## 8. 라벨링과 사용자 준비 사항

**기존 출력으로 다음 개선 작업을 시작하는 데 추가 라벨링이 필수는 아니다.** 속도 측정, 출력 비교, 실패 구간 진단, 교차 후보 생성은 지금 데이터로 계속할 수 있다.

**어떤 모델이 가장 정확한지, 실제 사건을 얼마나 놓치는지 결론 내려면 검수된 라벨이 필요하다.** 모델 재학습을 위한 라벨링이 아니라 평가용 정답 작성이다. 자동 초안을 활용하더라도 차량·차선·사건의 정답 검수는 필요하며, 사용자가 모든 프레임을 직접 그려야 한다는 뜻은 아니다.

| 목적 | 필요한 라벨 | 현재 상황 |
| --- | --- | --- |
| 차량 정확도 | 비교 프레임의 전체 차량 bbox, 제외 영역·라벨 완료 여부 | 원본1fps651장·자동 초안 준비, 미검수 |
| 차량 추적·사건 대상 평가 | 프레임 간 같은 차량 ID, 가림·진입·이탈, 사건 대상 차량 | 5fps549장·ID입력 항목 준비, 정답 미확정 |
| 차선 정확도·위반 유형 평가 | 차선 곡선, 가시성, 실선/점선, 색상, 중앙선 역할 | 곡선 초안·속성입력 항목 준비, 정답 미확정 |
| 후보 적중·시각 평가 | 기존 사건 구간·기록된 시작 시각, 대상 차량·차선 연결 | 기존 정답11구간 대조 완료: 기준 설정 C00·C09 두 구간, 원거리 실험 설정 C10·C44 포함 네 구간에 후보. 대상 일치 평가는 남음. 정밀 기하 교차 시각은 필요할 때 보충 |
| 정상 후보 발생량 | 정상 대상 목록과 실제 영상, 정상 여부 확인 | 영상 확보 필요 |

일부 대표 구간부터 라벨을 만들면 소규모 진단은 가능하다. 전체 모델 순위나 전체 precision/recall을 주장할 때는 평가 범위의 라벨 완성도를 충족해야 한다. 기존 사건 정보와 시각은 정답지에서 가져오며 사용자에게 다시 입력하도록 요구하지 않는다. 정상·독립 검증 영상 확보는 별도 잔여 과제다. 학습이나 모든 모델 재실행은 이번 정리의 필수 작업이 아니다.

Fine 단계 연결, #283·#325 반영, 운영 Search 통합·배포는 후속 별도 범위다. 현재 결과로 바로 운영 위반 판정을 적용하는 단계까지 완료한 것은 아니다.
