## 원인 확인과 변경 범위

기존 실패의 핵심은 forward/backward 검증을 통과한 배경점 중 RANSAC inlier가9–11개에 그쳐 최소12개를 충족하지 못한 것이었다. 실제 C05 전체300프레임에서 corner 간격만 바꾸는 통제 실험을 했다. 고정12px에서 실패68회,10px에서56회,8px에서53회,6px에서67회였다. 무조건 촘촘하게 바꿔도 좋아지는 것은 아니며 기존 성공 보정도 달라진다.

최종 구현은 기본12px 시도가 성공하면 즉시 반환한다. `MOTION_FAILED`이면서 corner/유효flow 수가 부족하거나, 모든 affine 시도가 inlier수(및 비율)만 부족한 경우 동일한 이전·현재 영상 쌍을8px 간격으로 한 번 더 처리한다. 실패 시 reset을 유지하고 보정 행렬을 만들지 않는다. 기본 시도와 재시도의 affine 결과·거절 사유·특징점 간격을 출력에 함께 기록한다.

차량·차선 마스크, 최대500corner, quality0.01, forward/backward 오차1px, 최소12inlier, 비율0.5, 잔차p95≤4px, 지지영역 폭·높이10%, 물리 변환과 장면 구조 조건을 모두 유지했다. `START`·`SCENE_CUT`, 물리 변환·지지영역 실패는 재시도 대상에서 제외한다. 이전 프레임 상태는 한 번만 갱신한다.

읽기 전용 병렬 진단에서 ROI 상단20%→5% 확대와 목적지 ROI만 확대는 핵심5쌍 모두 실패했다. 차량 마스크를 제거하면 일부 통과하지만 이동 차량이 카메라 보정을 오염시킬 수 있어 채택하지 않았다. 차선 마스크 제거도 한 쌍만 통과해 보호 마스크를 유지했다.

## 검증

- 실제 C0520.4→20.6초 원본 두 장·V1/L3 입력을 고정한 회귀: 수정 전 `MOTION_FAILED`,11inlier로 실패; 수정 후14inlier로 통과. identity가 아닌 실제 변환도 확인했다.
- 기본 성공 시 corner 재시도 금지 테스트와 기존 좁은 지지영역·장면 전환·관측 단절 보호를 포함해 관련38테스트 통과. 변경4개 Python 파일 LSP error0.
- 전체3,233프레임에서 기존 성공 결과의 affine·모델·기존 진단 필드 변화0. 새 간격/재시도 메타데이터는 별도로 비교했다. 기존4장면 전환 유지, 복구27프레임 모두 최종fit의 모든 gate통과.
- 실제 분석 CLI 종료0,3,233프레임·원시/병합 후보7개. CLI와 캐시 재생의 전체 CrossingFrame·후보가 정확히 일치했다.
- 출력30영상 전체decode,총6,466프레임,960×540. C05 전후16패널과 C00·C09·C10·C44 두 추적기8패널을 직접 확인했다.
- 입력·채택 규칙 해시가 이전 실행과 동일하고 CLI의 코드 해시가 현재 소스와 일치한다. 원본 정답 해시도 유지했다.

대상 차량·차선 의미·실제 타이어 접지 GT는 확정하지 않았다. 유형은 `UNKNOWN`, 점수는 미생성이며 사건 precision/recall은 계산하지 않는다.15개 영상은 이미 관찰한 개발 데이터다.
