원본 15개 영상과 기존 비교 캐시를 사용해 평가 라벨을 작성할 패키지를 만들었다. 모델을 다시 실행하거나 학습하지 않았다. 기존 사람 사건 정답 11건의 사건 종류·구간·기록된 시작 시각은 기존 평가 기준으로 재사용한다. 사용자에게 같은 사건과 시각을 다시 입력하도록 요구하지 않는다. 새 bbox·차선·대상 ID는 아직 정답으로 확정하지 않았다. 이미 예측을 관찰한 개발 데이터이므로 독립 평가 GT로 기록하지 않는다.

## 작성 방법

패키지는 [CVAT for images 1.1 공식 형식](https://docs.cvat.ai/docs/dataset_management/formats/format-cvat/)의 bbox·polyline·tag·attribute를 사용한다. 실제 CVAT 서버에 업로드하지 않았으며 서버에서의 가져오기·수정·내보내기까지는 아직 검증하지 않았다.

1. 패키지 `labels.json`을 작업의 라벨 정의로 설정한다. 작업별 `images.zip`으로 이미지 작업을 만든다. 연속 5fps 패널도 원본 영상의 fps로 재해석하지 않고 이미지 작업으로 사용한다.
2. 원본을 먼저 확인한다. `blank.xml`은 빈 라벨로 시작하는 버전이고, `draft.xml`은 수정할 자동 초안이다. 선택한 XML을 `CVAT for images 1.1`로 가져온다.
3. 차량은 승용차·승합차·버스·트럭 등 4륜 도로 차량을 표시한다. 이륜차·자전거·보행자는 제외한다. 보이는 외곽만 둘러싸고 화면 밖이나 가림 뒤까지 상자를 추정해 늘리지 않는다. 판독 불가 영역은 `IGNORE` 상자로 표시한다.
4. 1fps 작업에서는 모든 평가 대상 차량을 확인한다. 5fps 작업에서는 사건 대상과 혼동 가능한 이웃 차량을 고정하고 동일 차량의 `object_id`를 영상 안에서 유지한다. 자동 초안에 ID가 없으므로 사람이 붙여야 한다. 다른 5fps 패널에 같은 차량이 이어지면 동일 ID를 사용한다.
5. 선은 보이는 도색 중심을 `LANE` polyline으로 그린다. 동일 물리적 선에 `lane_id`를 유지한다. 가림이나 불연속 부분을 추측해 연결하지 않고 같은 `lane_id`에 다른 `segment_id`를 준다. 차체·보닛·와이퍼를 통과하는 자동 곡선은 제거·수정한다. 점선의 끊긴 부분도 가시 구간으로 나눈다.
6. `marking`은 SOLID/DASHED/DOUBLE/OTHER/UNKNOWN, `color`는 WHITE/YELLOW/OTHER/UNKNOWN, `role`은 LANE_BOUNDARY/CENTER_LINE/ROAD_EDGE/OTHER/UNKNOWN으로 기록한다. 색이나 종류가 보이지 않으면 UNKNOWN을 유지한다. 황색 연석을 중앙선으로 지정하지 않는다.
7. 해당 프레임의 `FRAME_REVIEW` tag에 검수자 `reviewer`를 적고 차량 검수 후 `reviewed=true`로 바꾼다. 1fps는 전체 차량 라벨 완료 후 `fully_labeled=true`도 지정한다. 일부 대상만 표시한 5fps 작업은 `fully_labeled=false`로 둔다. 차선 검수 완료는 별도 `lanes_reviewed=true`로 기록한다. `scene_cut`은 실제 영상 전환을 확인해 YES/NO로 기록하고 불확실하면 UNKNOWN을 유지한다.
8. 검수본을 `CVAT for images 1.1`로 내보내고 ZIP의 `annotations.xml`을 아래 변환 도구에 전달한다. 원본 `draft.xml`은 보존한다.

완전 가림·화면 이탈 시 bbox를 만들어 채우지 않는다. 5fps 가림 구간과 대상의 진입·이탈은 사건 메모와 프레임별 가시 관측 공백으로 함께 확인한다. 영상 밖의 촬영 차량이 사건 주체인 경우 `target_kind=EGO`, `target_id=EGO`로 사건에 기록하고 촬영 차량 bbox를 억지로 만들지 않는다. 외부 차량 탐지 평가의 대상 범위 차이는 이후 평가에서 따로 보고한다.

## 기존 사건 정답 재사용과 부족한 라벨 보충

기존 로컬 정답지 `src/daesingo/search/video/정답지.md`의 사건 종류와 `t_start–t_end`, 괄호 안 `t_onset`을 평가 기준으로 재사용한다. 예를 들어 C00은 10–14초(시작 12초), C05는 10–12초(시작 11초)와 20–22초(시작 21초)로 이미 기록되어 있다. 같은 사건의 발생 여부나 시각을 사용자에게 다시 묻지 않는다. 시작 시각이 없는 항목은 원래 구간을 유지한다.

`events.reference.json`은 기존 사건 구간을 보존한다. `events.template.json`과 작성 중인 `events.annotations.json`은 부족한 대상·차선 연결 정보를 보충하는 용도다. `events-review.csv`와 JSON은 자동 동기화되지 않는다. 추가 정보가 미검수여도 기존 사건 정답이 미작성 상태로 바뀌지는 않는다.

- 차선 모델 평가의 우선 작업은 실제 도색 중심 좌표와 누락·잘못된 곡선을 확인하는 것이다. 차선 종류·색·역할은 보이는 근거만 기록한다.
- 차량 탐지·추적과 전체 사건 판단 평가에는 차량 bbox, 동일 차량 `object_id`, 사건의 `target_kind`·`target_id`·`lane_id` 연결을 보충한다. 확인 못한 추가 필드는 UNKNOWN/null로 유지한다.
- `crossing_time_sec`는 별도의 정밀 기하 교차 시각이다. 현재 사용자 검수의 필수 항목이 아니다. 기존 `t_onset`과 의미가 같다고 가정해 복사하지 않는다. 정밀 교차 오차를 평가하는 단계에서 필요할 때만 원본과 교차 전후 프레임으로 보충한다.
- `reviewed`, `reviewer`, `status`는 추가 라벨의 검수 상태다. 자동 초안을 정답으로 확정하지 않는다. 기존 정답과 사용자 관찰이 충돌하면 관찰 메모를 보존하고 원본을 대조하며 기존 정답을 자동 덮어쓰지 않는다.

채팅에서 받은 C00·C05 관찰은 보충 메모다. 사건 11건을 다시 확인받는 진행률이나 필수 체크리스트로 사용하지 않는다. 사건·프레임 라벨을 연결하는 전체 평가 CLI는 3번 작업의 대상이다.

## 변환과 재현

저장소 루트에서 실행한다. 준비 스크립트는 기존 출력 디렉터리를 덮어쓰지 않는다. 준비 입력은 기존 실험 캐시이고, 결과에는 모델 실행이나 재학습이 포함되지 않는다.

```powershell
$python = '.omc/aihub-models/cv-lane-track-v1-2026-10-09/tracking-venv/Scripts/python.exe'
$pack = '.omc/aihub-models/cv-lane-track-v1-2026-10-09/label-preparation-2026-10-10-v1'

# 검수 XML을 새 디렉터리로 변환한다.
& $python -m scripts.cv_lane_track_label_import reviewed.xml `
  "$pack/tasks/01_YT_0002_C00_5fps_00/input_manifest.json" reviewed-c00

# 차량 라벨의 검수 여부를 확인한다. 실제 검출 지표를 계산하는 명령은 아니다.
& $python -m scripts.cv_lane_track_vehicle_score reviewed-c00/vehicles.jsonl

# 패키지 재생성. NEW_OUTPUT은 아직 존재하지 않는 경로여야 한다.
& $python -m scripts.cv_lane_track_label_prepare `
  '.omc/aihub-models/cv-lane-track-v1-2026-10-09' NEW_OUTPUT
```

변환 결과는 `vehicles.jsonl`, `lanes.jsonl`, `review_ledger.json`이다. importer는 작업의 모든 이미지 이름과 크기·해시를 확인한다. missing/duplicate 이미지, 범위 밖·비정상 bbox, 검수자 누락, 검수된 5fps의 객체 ID 누락, 중복 ID를 거부한다. 자동 초안은 reviewed=false 그대로 변환되고 기존 차량 평가 경계에서 거부된다. 전체 차량 지표는 검수된 651장과 fully_labeled 조건을 모두 충족해야 한다.

- 관련 테스트 **26개 통과**, 변경된 5개 파일 LSP 오류 0, 코드 규칙 검사 0건.

- draft XML → JSONL 변환 **1,200프레임 완료**, 미검수 작업 **29/29개 평가 차단**.
- 첫 4개 작업과 보조 정상 1개 작업의 원본·초안 시트 10장, 서로 다른 원본 시점 30개를 직접 확인했다. 이는 검수 자료의 표시·내용 확인이며 해당 30개 시점의 GT 정답 확정은 아니다.

최종 패키지는 `label-preparation-2026-10-10-v1`이다. 같은 날짜의 접미사 없는 초기 패키지는 SUPERSEDED로 표시했다. source snapshot, 입력·코드 해시, ZIP/변환 감사 결과는 최종 패키지 `source/`, `provenance.json`, `artifact_audit.json`에 보관한다. `roundtrip-audit/`는 자동 초안 변환 검사 결과로, 검수된 GT가 아니다.
