# CV_LANE_TRACK v1 — UNKNOWN 교차 후보 실행 결과

작성일: 2026-10-10. 상태: **전체 실행·산출물 감사·정성 검수 완료**. 사용자가 승인한 다음 단계인 차량·차선 상대 위치 기반 후보 생성을 실행했다. 임시 V1 차량 검출＋L3 UFLDv2 차선과 두 추적기의 기존 캐시를 사용했다. 이번 결과는 정확도 비교나 위반 판정이 아니다.

15영상 전체를 5fps로 처리한 3,233프레임에서 ByteTrack 2개, BoT-SORT 3개의 UNKNOWN 후보를 생성했다. raw 5개와 병합 후 5개를 모두 보존했다. 같은 차량·시각을 두 추적기가 함께 제안한 경우가 있어, 합계 5개는 서로 다른 사건 5개를 뜻하지 않는다. 화면상 제안 구간은 3개다. 후보가 없는 나머지 12영상도 고정된 연속 화면으로 확인했다.

## 실제 후보와 육안 관찰

대표 시각은 원본 영상의 초 단위다. 방향은 화면에서 차선에 대한 bbox 하단 중앙의 상대 위치 부호이며 차량의 실제 지면 이동 방향과 같다고 보장하지 않는다.

| --- | --- | ---: | --- | --- |
| YT_0002_C00 | ByteTrack T62/L74 | 13.501초 | 11.501–15.501초 | 흰 세단의 지속적인 왼쪽 이동과 추정 경계 상대 위치 변화가 보임 |
| YT_0002_C00 | BoT-SORT T55/L74 | 13.501초 | 11.501–15.501초 | 위와 같은 검출·거리 trace |
| YT_0001_C33 | ByteTrack T163/L48 | 13.087초 | 11.087–15.087초 | 오른쪽 SUV 일부가 화면 밖으로 잘려 박스 중심과 실제 접지 위치가 다를 수 있음 |
| YT_0001_C33 | BoT-SORT T116/L48 | 13.087초 | 11.087–15.087초 | 위와 같은 검출·거리 trace |

C00의 거리 d는 마지막 안정 관측 +19.0px에서 최초 반대쪽 −64.9px, 확인 시점 −146.0px로 변했다. 원본에서 추정 중앙 경계를 가로지르는 움직임이 보이지만 후면 blur·가려진 선·bbox 접지 대리점 때문에 정확한 바퀴 교차 시각은 미검증이다. 선의 황색/실선 여부와 위반 여부는 자동 분류하지 않았다.

C33은 −7.5→+9.67→+46.67px다. 초기 관측의 박스 오른쪽은 원본 폭640에서 x639에 걸려 있다. 카메라 이동·차선 추정 변화와 잘린 박스가 영향을 줄 수 있으므로 실제 교차로 확정하지 않았다. 13.0초 motion 실패로 상태를 끊은 뒤 새 경계에서 기준점을 잡고 13.2–13.6초 반대편 유지 조건을 만족했다. 실패 이전 구간을 이어 붙이지 않았다.

C10은 −2.5→+4.5→+7.5px다. 처음 차량 폭27px, deadband2px로 반대편 유지 규칙은 통과했다. 그래프에서 지속적인 상대 변화가 보이지만 원거리·작은 여유 픽셀·추정 차선 때문에 오차와 실제 교차를 구분할 정답이 필요하다. BoT-SORT만 후보를 냈다는 사실로 더 좋은 추적기라고 결론내리지 않는다.

## 고정한 규칙

- 현재 검출 bbox 하단 중앙에서 같은 y의 차선 x를 빼 d를 계산했다. 실제 바퀴 접지점은 아니다. 가시 y 범위를 벗어나면 외삽하지 않았다.
- 차선 출력 slot 대신 시간 연결된 lane ID를 사용했다. 배경 sparse optical flow＋RANSAC partial affine로 이전 곡선을 정렬하고 공통 y 범위에서 일대일 대응했다. 모호한 연결·급변은 거부했다. 부분 affine은 도로 원근/깊이를 완전히 설명하지 못한다.
- ε=max(2px, bbox폭×0.05). 반대편에서 최소3관측과 0.4초를 모두 만족해야 후보를 냈다. 부호 변화 구간을 선형 보간해 대표 시각을 구했다.
- 0.45초 초과 관측 공백, 차선 소실, 유효 접지 거리 없음, motion 실패는 상태를 끊었다. 포함률0.8 이상 겹침 차량 박스는 양쪽 관측을 보류했다.
- HSV H/S 32×32 histogram, 320×180영상, Bhattacharyya거리>0.45면 장면 전환 reset. 캐시 추적기를 다시 실행하지 않고 scene epoch로 차량 ID 범위를 분리하고 차선/교차 상태를 초기화했다.
- 대표 시각 ±2초를 원본 길이에 맞춰 저장했다. 같은 영상·추적기·epoch·차량·경계·방향의 2초 이내 후보만 병합했다. 이번에는 병합으로 줄어든 후보가 없다.
- L3 confidence는 null이므로 후보 score도 null이다. 임의 점수를 만들거나 top3를 고르지 않았다. 전체 후보와 UNKNOWN 의미를 보존했다.

규칙과 8개 소스 파일 SHA256은 실행 전에 고정했고 결과를 본 뒤 threshold나 핵심 코드를 변경하지 않았다. 규칙 SHA256은 `4d7a719c04c21e91b98b38fea634f3e6c76fca8ad54639bc15ef22d8a069b366`이다.

곡선/거리 수는 프레임별 관측 합계이며 고유 차선·차량 수나 정확도 지표가 아니다. 후보가 없는 영상이 차로 유지 또는 정상이라는 뜻도 아니다. 차량이 작거나 가려지고, 차선이 차량 몸체·와이퍼를 따라 흔들리거나 없어지며, 보정 실패로 시간 연결이 자주 끊겼다. 특히 AVI·터널 구간의 잦은 reset은 후보 누락 원인이 될 수 있다.

장면 전환으로 판단한 5곳을 모두 앞뒤 원본으로 확인했다. 141956 3.399초, 150504 19.992초, C39 17.4/17.8초, C47 48.0초는 모두 같은 주행 장면이 이어지며 터널/고가 아래 조도·노출·와이퍼 변화가 보였다. histogram 규칙이 이런 변화를 장면 전환으로 취급하는 한계가 있다. 이번 고정 실행의 증거를 유지했고 사후 완화는 하지 않았다.

## 실행·검증 근거

추론·기존 추적을 제외한 캐시 읽기, 이미지 해시 검증, 움직임 정렬, 차선 연결, 상태 계산, overlay와 전체영상 저장까지 **95.79초** 걸렸다. 실제 최종 서비스 처리량이나 모델 전체 처리시간으로 해석하면 안 된다. Python3.12.2, NumPy1.26.4, OpenCV4.10.0.84, lap0.5.12, Ultralytics8.4.133, Pydantic2.13.5인 기존 tracking 환경을 사용했다.

산출물 감사는 manifest 순서·3,233프레임 일치, 입력/규칙/실행 전 소스 해시 일치, 두 추적기의 원래 검출 박스·ID 일치, 차선 ID 중복 없음, reset 이후 연결 단절, 후보 관측 provenance·부호/deadband/유지 시간/보간·병합 범위를 확인해 PASS했다. 전체 출력30MP4를 끝까지 decode해 각 클립의 프레임 수·5fps·960×540을 확인했다. 추가 후보5MP4는 원본＋overlay 1920×540, 각각 실제 관측20프레임이며 모두 decode PASS다. 원본 시각은 프레임에 표시한다.

육안 검수는 **30장**이다: 전체15클립 각각 중간6연속프레임(원본90시점＋두 추적 결과), 후보5개 각각 기준/최초 반대편/확인 시점, 거리 그래프5장, reset5곳 앞뒤 원본. 전체 MP4를 사람이 처음부터 끝까지 재생한 검수는 아니다. 정성 관찰은 위에 기록했고 bbox·ID·차선 GT 또는 사건 정답 라벨로 사용하지 않았다. 출력 확인 후의 라벨링은 모델 출력을 보지 않은 독립 평가로 소급할 수 없다.

현재 관련 테스트 **18개 통과**, 변경11파일 compileall·Python 규칙 검사·LSP error 없음. 상태 공백/누락/반전, slot 변경·모호한 경계, 실제 optical flow의 원본 좌표 변환, 장면 전환, 겹침 억제, 접지 경계 급변, 실제 CLI 양성 실행·덮어쓰기 거부를 검증했다. 기본 프로젝트 환경에서는 상태8개 통과, ML 의존성이 없는 2모듈 skip이다. 별도 읽기 전용 리뷰는 코드와 산출물 감사 범위에서 CLEAR/APPROVE이며 육안 검수는 실행자가 직접 수행했다.

## 로컬 산출물과 재현

캐시는 `.omc/aihub-models/cv-lane-track-v1-2026-10-09/tracking-diagnostic/`, 출력은 같은 상위 폴더의 `crossing-candidates-2026-10-10/`다. 원본 영상·대형 캐시는 Git에 추가하지 않았다.

- `frames.jsonl`: 시간 연결 lane ID, 실제 차량 관측, 거리 trace와 거부·reset 근거.
- `raw_candidates.json`, `candidates.json`, `summary.json`: 전체 후보·원본 구간·진단·입력/코드 해시.
- `ByteTrack/videos/`, `BoT-SORT/videos/`: 전체30개 overlay 영상.
- `candidate_videos/`: 후보5개 앞뒤2초의 원본＋overlay 비교 영상. `candidate_video_audit.json`에 관측 frame ID·구간·해시.
- `review/`: 연속/후보/reset 비교 화면, 거리 그래프 PNG＋SVG.
- `artifact_audit.json`, `manual_qa.json`, `review_selection.json`: 감사·실제 본 화면 해시·사전 선택 정책.

새 빈 출력 폴더를 지정해 재현한다. runner와 review는 기존 증거 덮어쓰기를 거부한다.

```powershell
$py = '.omc/aihub-models/cv-lane-track-v1-2026-10-09/tracking-venv/Scripts/python.exe'
$base = '.omc/aihub-models/cv-lane-track-v1-2026-10-09'
& $py -m scripts.cv_lane_track_crossing_run "$base/tracking-diagnostic" "$base/crossing-rules-2026-10-10.json" "$base/crossing-reproduction"
& $py -m scripts.cv_lane_track_crossing_review "$base/crossing-reproduction"
```

추가5개 비교 MP4는 감사 단계에서 기존 원본 프레임과 동일한 `render_crossing`으로 생성했다. 위 review 명령은 기본 비교 시트와 그래프를 생성한다.

`실행 계획`(로컬 자료), `코드·감사 리뷰`(로컬 자료), [이전 추적 결과](cv-tracking-diagnostic-2026-10-09.md), `원래 실험 계획`(로컬 자료).

GT 기반 모델/추적기 선정, 정확도·Recall@K·오탐률, 실선/점선·황색 분류, C0–C5 ablation, Fine 전달·배포는 이번 결과에 포함하지 않는다. 다음 실험에서는 이번 실행을 기준으로 장면 전환·motion/차선 연결 실패와 원거리·화면 가장자리 접지 대리점 오류를 구분해 검증할 필요가 있다.
