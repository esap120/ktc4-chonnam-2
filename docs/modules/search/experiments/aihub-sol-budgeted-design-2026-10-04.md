# AI Hub 후보 + sol Fine: 입력량·차선 표시·프롬프트 실험 설계

2026-10-04 · 설계 문서 · 아직 실행하지 않음

**목표는 현재 확인한 사건을 유지하면서 입력 토큰을 줄이고, 차선 표시와 프롬프트 변경의 효과를 분리하는 것이다.** 먼저 같은 후보 51개에서 앞뒤 여유와 fps만 비교한다. 비용·판정 유지 기준을 통과하면 작은 진단 패널에서 이미지 표시 × 프롬프트를 비교한다. 마지막에 선택한 조건을 전체 영상에서 재검증한다. 단계별 예산은 제안값이며, 실행 요청 시 이 문서를 기준으로 사전 계산한다.

## 실행 순서

1. **기준 자료와 실행 입력을 고정한다.** 아래 기준 파일·해시·영상 15개·후보 51개·프롬프트·순서를 검증하고, 조건별 이미지 수와 예상 토큰을 로컬에서 계산한다. 완료 기준은 모든 해시와 호출 목록이 기록되고 각 조건이 단계 예산 안에 들어오는 것이다.
2. **1단계에서 5초 본문을 시험한다.** A1을 먼저 실행하고 사전 정의한 분기대로 A2 또는 A1R을 실행한다. 완료 기준은 실행한 각 조건의 후보 51개 응답·실패·사용량·사건별 결과가 빠짐없이 채점된 것이다.
3. **1단계 통과 시 2단계 2×2 비교를 실행한다.** 시간·fps 조건을 고정하고 12개 진단 후보에 이미지 표시와 프롬프트 두 요인만 바꾼다. 완료 기준은 4조건 × 12후보의 판정·실패·이미지·토큰 기록과 원본 대조 검토가 있는 것이다.
4. **2단계에서 개선 후보가 있으면 3단계 전체 비교를 실행한다.** 같은 입력량의 원본 대조군과 선택 조건을 15개 영상·51후보에서 각각 2회 비교한다. 완료 기준은 반복별 비용·판정·오탐·불확실성·실패를 공개 결과에 분리한 것이다.
5. **결과에 따라 채택·보류를 기록한다.** 모든 단계의 결과를 이 문서의 판정 기준과 대조한다. 예산 초과·성능 손실·근거 부족으로 멈춘 단계는 실행하지 않은 상태로 보고한다. 일부 후보만 끝낸 결과를 전체 성능으로 발표하지 않는다.

## 공통 통제와 예산

추론에는 영상·시간·LRCN 예측과 표시용 모델 출력만 전달한다. 기존 후보를 그대로 사용해 조건 간 Coarse 차이를 제거한다. 정답 구간·종류·수작업 대상 힌트는 채점 단계에서 읽는다. 후속 단계를 고르는 기준은 사전에 정한 개발 실험 분기이며, 독립 검증 데이터에서의 성능 주장과 구분한다.

영상은 원본 비율을 유지하고 높이 720px까지만 줄인다. 360p 원본을 확대하지 않는다. detail·응답 스키마·모델·추론 설정은 조건 사이에서 유지한다. fps를 바꾸면 프롬프트의 실제 fps 안내도 바꿔 시간 해석 오류를 막는다. fps 안내와 실제 시작·종료 시각 외에 1단계 프롬프트 의미를 바꾸지 않는다.

| 단계 | 신규 API 총 토큰 상한, 제안 | 포함 범위 |
|---|---:|---|
| 1단계 | 1,800,000 | A1 51회 + A2 또는 A1R 51회, 최대 102회 |
| 2단계 | 700,000 | 4조건 × 12후보, 48회 |
| 3단계 | 2,500,000 | 원본 대조군·선택 조건 각각 2회 × 51후보, 204회 |

상한은 단계마다 독립적이다. 후속 단계는 앞 단계의 통과 조건과 사전 예산 검증을 만족할 때만 실행한다. 3단계에서 최대 204회를 채우는 것보다 비용·완결성 조건이 우선이며, 예산상 완주할 수 없으면 시작하지 않고 설계를 보류한다.

사전 예상량은 실제 프레임 크기·장수의 이미지 토큰, 호출당 비이미지 입력 여유 1,500토큰·출력 여유 3,000토큰을 합산한다. 이미지 계산 근거는 [OpenAI Docs](https://developers.openai.com/api/docs/guides/images-vision)이며 프록시의 실제 usage도 매 호출 저장한다. 잔여 예산이 다음 호출 예상량보다 작으면 신규 호출을 멈춘다. 출력 여유는 추정치이며 완벽한 청구 상한이 아니므로, 예상 대비 초과량도 보고한다. 비용을 이유로 원본이나 정상 후보를 몰래 제외하지 않는다.

본문 5초·2fps에서 3단계가 원본 대조군과 표시 추가 조건을 각각 2회 비교하면, 위 여유를 포함한 예상량은 2,275,824토큰으로 제안 예산 안에 들어온다. 같은 비교를 4fps로 하면 3,320,304토큰으로 예산을 넘는다. 4fps 조건만 성능 유지에 성공하더라도 후속 비교 예산을 자동으로 늘리지 않고, 그 단계의 결과와 보류 이유를 보고한다.

## 1단계: 여유 구간과 fps 분리

| 조건 | 앞뒤 여유 | 원본 시퀀스 fps | 변경 요인 | 순서 |
|---|---:|---:|---|---|
| H0 | 4초 | 4 | 기존 기록 | 재사용 참고 기준 |
| A1 | 0초 | 4 | H0 대비 여유 구간만 제거 | 첫 실행 |
| A2 | 0초 | 2 | A1 대비 fps만 감소 | A1이 네 사건을 유지하고 정상 오탐이 없을 때 |
| A1R | 1초 | 4 | A1 대비 여유 1초만 복원 | A1이 네 사건 중 하나를 잃거나 정상 오탐을 낼 때 |

각 신규 조건은 모든 51개 후보를 1회 실행한다. A2와 A1R은 같은 분기에서 둘 다 실행하지 않는다. A1R 이후의 1초·2fps 조합은 이 초기 분기에서 실행하지 않고, 1단계 결과를 보고 다음 실험을 설계할 때 검토한다. 이렇게 한 번에 바뀌는 요인을 제한한다.

A1은 후보별 20장, 총 1,020장이고 이미지 토큰 추정은 522,240이다. A2는 후보별 10장, 총 510장이고 이미지 토큰 추정은 261,120이다. H0의 나머지 입력·출력을 그대로 가정하면 총량은 각각 약 607,068·345,948토큰이지만, 이는 예측값이며 실제 프롬프트·응답 사용량으로 갱신한다.

C00의 후보 index 14는 7.5–12.5초라 횡단 후 장면이 부족할 수 있다. C47의 index 38은 2.5–7.5초라 정답 0.5–3초와 일부만 겹친다. 이러한 경계 사례를 줄인 입력의 한계로 따로 기록한다. 정답을 보고 후보 위치를 옮겨 보완하지 않는다.

**2단계에 넘길 시간·fps 조건 T의 기준:** 기존 네 사건을 모두 유지하고, 정상 후보의 OBSERVED가 0이며, 51호출이 완결되고, 실제 총 토큰이 H0의 50% 이하인 조건이다. API·시각 범위 오류가 있는 실행은 성능 유지로 채택하지 않는다. 여러 조건이 통과하면 실제 토큰이 가장 적은 조건을 선택한다. 실제 토큰이 같으면 더 높은 fps를 선택한다.

조건 T가 없으면 1단계에서 보고서를 작성하고 후속 단계는 보류한다. 네 사건 유지·50% 절감은 이번 설계의 탐색 목표이며 통계적 비열등성을 입증하는 기준이 아니다. H0는 기존 1회 기록이라 A1과의 차이에는 모델 변동도 포함된다. 동시 통제 비교는 3단계에서 별도로 수행한다.

## 2단계: 대표 차선 표시 × 프롬프트 2×2

시간·fps는 T로 고정한다. 모든 조건에 원본 시퀀스와 같은 두 대표 원본 이미지를 보낸다. 표시 조건에만 그 두 원본의 모델 표시 버전을 추가한다. 이 구조에서 토큰 차이는 추가 표시 이미지와 프롬프트 때문이며 crop·차량 박스·해상도·후보 변경이 끼어들지 않는다.

| 조건 | 이미지 | 프롬프트 |
|---|---|---|
| B00 | 원본 시퀀스 + 대표 원본 2장 | P0 |
| B01 | B00과 같은 원본 | P1 |
| B10 | B00 + 대표 차선 표시 2장 | P0 |
| B11 | B10과 같은 이미지 | P1 |

비교는 B01−B00으로 프롬프트 효과, B10−B00으로 표시 효과, B11−B10으로 표시가 있을 때의 프롬프트 효과를 본다. B11 하나만 좋아졌다고 두 요인이 각각 효과 있다고 해석하지 않는다.

### 고정 진단 패널

후보 파일 해시를 기준으로 index `0, 3, 6, 7, 10, 14, 17, 24, 33, 38, 39, 49`의 12개를 고정한다. **정답 구간을 참고해 선택한 진단 패널**이며 Coarse 성능이나 전체 영상 검출률을 평가하는 표본으로 사용하지 않는다. 기존 네 성공 사건·다섯 미검출 사건·정상 세 영상을 포함해 모델의 관찰 변화를 저비용으로 확인한다. 정답 정보는 패널 선택·채점에만 쓰고 추론 요청에 넣지 않는다.

| 구분 | 후보 index | 영상 |
|---|---|---|
| 기존 성공 | 3, 10, 14, 17 | 141927, youtube_clip_01, C00, C08 |
| 기존 미검출·본문 포함 | 24, 33, 38, 39, 49 | C33, C39, C47, C10, C44 |
| 정상 | 0, 6, 7 | 141628, 141956, 150504 |

index 6은 정상 점선 변경 10–14초와 일부 겹치는 후보라, index 5의 이른 정상 주행보다 차선 오인식 검증에 적합하다. 짧은 구간이 정상 변경 전체를 포함한다는 뜻은 아니다. C05 두 사건과 C09의 후보 누락 문제는 이 패널로 개선됐다고 주장하지 않는다.

후보 index를 오름차순으로 순회하며 각 후보의 네 조건 순서를 후보 index를 4로 나눈 나머지만큼 순환 이동한다. 조건별 고정 실행 순서에 따른 모델·서비스 변동을 줄인다. 각 조건은 1회이며, 작은 패널에서의 우연한 차이를 최종 개선으로 선언하지 않는다.

### 대표 이미지와 마스크 표시

대표 시각은 후보 본문 시작+길이의 25%·75%에 가장 가까운 **본문 안의 서로 다른 두 캐시 프레임**이다. 거리가 같으면 이른 프레임을 선택한다. `.omc/aihub-models/run/manifest.json`의 실제 frame_times를 사용하고, 캐시 원본 JPEG와 같은 시각의 예측만 연결한다. 예측 마스크를 이웃 시각에 전파하지 않아 1fps 마스크가 다른 프레임의 정답처럼 보이는 오류를 막는다.

원본 대표 이미지와 표시 이미지는 같은 JPEG에서 만들고 함께 축소한다. mask RLE 크기가 원본 크기와 일치하는지 검사한다. 캐시 프레임이나 예측이 없으면 해당 후보의 네 조건을 임의 이미지로 채우지 않고 준비 실패로 보고한다. 테스트 전에 이 12개 모두 준비 가능한지 확인한다.

| 표시 모델 | 표시 클래스 | 화면 표시 색 |
|---|---|---|
| mask_lane | white_solid | 청록 |
| mask_center | yellow_solid, yellow_double_solid | 자홍 |
| mask_stop | stop_line | 주황 |

score ≥0.5의 예측을 alpha 0.2로 표시하고 종류·점수를 붙인다. 화면 색은 실제 차선 색과 구분하는 인공 색이다. 학습 마스크는 넓게 buffer된 영역이므로 정확한 선 중심·접촉 순간 표시라고 부르지 않는다. 차량 박스·영역 모델·신호 박스는 이번 비교에서 추가하지 않아 차선 표시 효과를 분리한다. 모든 프레임에 표시를 복제하지 않고 대표 2장만 추가한다.

T가 본문 5초·2fps라면 패널의 기본 원본 시퀀스+대표 원본은 조건당 이미지 토큰 약 100,224, 표시 추가 조건은 약 116,928로 추정된다. 네 조건 합계는 이미지 부분 약 434,304다. T가 달라지면 예산을 다시 계산하고 700,000토큰 안에 완주할 수 있을 때만 실행한다.

### P0·P1과 공통 입력 안내

P0는 기존 `scripts/aihub_lrcn_prompt.py`의 분류 참고·독립 세 종류 확인 지침이다. P1은 아래 관찰 절차를 덧붙인다. 모델·FineResponse는 그대로 유지한다.

두 프롬프트 모두 같은 공통 입력 안내 S를 앞에 둔다. S에는 원본 시퀀스 fps, 이미지별 SOURCE_SEQUENCE / SOURCE_REPRESENTATIVE / MODEL_OVERLAY 역할, 원본·상대 시각, 표시 색 범례, 모델 표시가 미확정 예측이라는 사실을 넣는다. 대표·표시 이미지까지 연속 fps 시퀀스라고 설명하지 않는다. B00·B01에도 같은 범례를 제공하고 해당 호출에 실제 포함한 이미지 역할을 명시한다. P0+S와 P1+S의 텍스트·해시를 고정해 조건 간 안내 차이를 막는다.

P1에 추가할 지침 초안:

> 원본에서 주변 차량 각각을 살펴보고, 촬영 차량의 정지 여부와 다른 차량의 움직임을 분리하라. 같은 차량을 전후 이미지에서 확인한 뒤 실제 선 횡단과 원본 선의 색·실선·점선 형태를 각각 확인하라. 모델 표시와 원본이 다르면 원본을 근거로 표시 오류를 기록하라. 표시의 존재·높은 점수만으로 위반을 확정하지 마라. SIGNAL은 그 차량에 적용되는 신호와 적색 상태의 정지선 통과를 함께 확인하라. 후보 종류와 다른 종류도 검토하라. 횡단 전·중·후의 관찰 시각을 temporal_facts에 남기고, 대상이나 횡단 순간이 가려져 확인할 수 없으면 UNCERTAIN으로 답하라. 관찰한 범위에서 사건이 없으면 NOT_OBSERVED로 답하라.

차량 좌표 힌트가 없으므로 match_with_hint는 null이다. P1에서 부재와 증거 부족을 구분한 결과를 별도로 집계한다. UNCERTAIN 증가를 검출 개선이나 정상 기각 성공으로 바꿔 계산하지 않는다. 프롬프트 최종 문자열은 호출 전에 파일로 저장하며 결과를 본 뒤 수정한 버전은 별도 실험으로 분리한다.

**3단계 후보 선정 기준:** 모든 12호출이 오류 없이 끝나고 기존 네 성공 사건을 유지하며, 정상 세 후보의 OBSERVED가 0인 B01·B10·B11을 평가한다. B00보다 패널 사건 판정이 많거나, 판정 사건을 모두 유지하면서 실제 총 토큰이 더 적은 조건만 개선 후보로 삼는다. 패널에서 회복된 판정은 원본·시간·차량 근거 검토를 통과해야 한다. 개선 후보 중 실제 총 토큰이 가장 적은 것을 택하고, 토큰이 같으면 사건 판정이 많은 조건, 두 값도 같으면 표시 이미지가 없는 조건을 택한다. 개선 후보가 없으면 표시·프롬프트 효과를 확인하지 못했다고 보고하고 3단계는 보류한다.

## 3단계: 고정 원본 입력에서 전체 재검증

대조군은 T + 원본 시퀀스·대표 원본 + P0+S다. 비교군은 T + 2단계 선택 조합이다. 각각 후보 51개를 2회, 합계 최대 204회 실행한다. 2단계 패널 선정 때 보지 않았던 후보도 포함해 진단 패널 효과가 전체에서 유지되는지 확인한다. 개발 영상 자체는 이미 사용했으므로 독립 평가로 부르지 않는다.

대표 시각 선택은 51개 모두에 같은 규칙을 적용한다. 대조군·비교군에서 후보 위치·fps·시각·원본 픽셀·대표 원본을 동일하게 고정한다. 반복별 조건 순서를 반대로 배치하고, 모델 반환·파싱·시각 오류와 총량을 기록한다. 기존 H0를 이 비교의 동시 대조군으로 재사용하지 않는다.

최종 후보는 두 반복 모두 오류 없이 51호출을 끝내고 기존 네 사건을 유지하며 정상 후보 OBSERVED가 0이어야 한다. **비교군의 완결된 51호출 실행당 실제 총 토큰을 두 반복에서 평균한 값**이 633,822토큰 이하, 즉 H0보다 50% 이상 적어야 한다. 대조군 비용을 섞어서 비교군 비용을 낮춰 보이지 않는다. 비교군은 같은 시간·fps·원본 이미지의 새 대조군보다 각 반복의 사건 판정이 적지 않아야 한다. 판정 사건을 모두 유지하면서 비용만 늘어난 조건은 채택하지 않는다. 소표본 2회가 일반 성능·통계적 비열등성을 입증하는 것은 아니다.

## 채점·검토·실패 처리

| 항목 | 정의와 목적 |
|---|---|
| 후보 시간 포함 | 모든 13사건에 대해 본문·실제 Fine 입력 중첩을 따로 계산해 후보 누락과 Fine 실패를 분리 |
| 기존 비교 지표 | 오류 없는 OBSERVED + 반환 종류 일치 + 실제 입력 구간 중첩, 사건 중복은 한 번만 계산 |
| 네 사건 보존 | 합계뿐 아니라 기존 네 사건 각각의 유지 여부를 확인해 성공 교체를 숨기지 않음 |
| 정상 후보 오탐 | 정상 영상 후보에서 OBSERVED를 낸 호출·영상 수, 미호출·오류는 정상 기각 성공으로 세지 않음 |
| 불확실성 | UNCERTAIN·NOT_OBSERVED·실패를 분리해 저렴한 조건의 판단 유보 증가를 확인 |
| 관찰 근거 | 모든 OBSERVED와 새로 판정이 바뀐 사건의 원본 대상·차선·관련 신호·횡단 시각을 검토 |
| 사용량 | 호출·해상도·이미지 역할별 장수·원본/표시 중복 해시·실제 입력/출력·지연·예상량 차이 |

검토는 조건명을 가린 응답과 원본을 먼저 대조하고 그 뒤 조건을 연결한다. 모델이 MATCHED라고 쓴 것만으로 대상 차량을 맞혔다고 인정하지 않는다. C00의 기존 index 13처럼 구간이 겹쳐도 보고한 횡단 시각이 정답 밖인 응답은 시간 불일치로 별도 표시한다. 정답 시각 근거가 부족한 사건은 미확인 상태를 보존하고 제공 GT를 모델 응답에 맞춰 수정하지 않는다.

정밀 차량 GT가 없으므로 기본 수치를 검증된 위반 차량 recall로 부르지 않는다. 경계에서 일부 구간만 포함한 것·횡단 후 확인 부재·시각 표본 해상도를 실패 원인에 남긴다. FineResponse는 호출당 한 사건만 반환하므로 후보 병합으로 긴 구간을 만드는 실험은 이번 범위에서 제외한다. 여러 사건을 한 호출에 담는 설계는 이 실험 후 중복 비용이 여전히 큰 경우 복수 사건 응답과 함께 별도로 검토한다.

반환 모델이 다르면 해당 호출을 실패로 저장하고 이후 호출을 중단한다. API·파싱·추출·응답 시각 오류도 정상 기각으로 처리하지 않는다. 재시도는 0이며 원인 수정·재실행은 별도 시도 ID로 남긴다. 정답이 없는 호출과 예산 때문에 미완료한 호출을 숨기지 않는다.

## 구현 경계와 산출물

실행기는 현재 `scripts/aihub_hybrid_fine.py`의 고정 padding=4·fps=4 경로를 실험 조건으로 지정할 수 있게 확장해야 한다. 대표 원본·overlay 역할과 시각을 기록하는 입력 manifest, 실제 요청·출력·예산 ledger, 조건별 checkpoint를 추가해야 한다. 현재 CLI에 없는 옵션으로 실행 명령을 문서에 제시하지 않는다. 구현 후 후보 선택·추출·표시 정합·시각 환산·예산 중단·기존 채점과의 호환성을 검증한다.

실험별 `.omc/aihub-models/budgeted-sol-2026-10-04/` 아래 입력 manifest·프롬프트·응답·표시 검토 이미지·QA와 결과 원본 JSON·JSONL을 로컬에 보존하고, 저장소에는 비밀 설정·응답 원문을 제외한 한국어 요약 보고서를 둔다. manifest에는 후보 해시, 실행 소스·프롬프트 해시, arm·repeat·candidate index, 실제 시각·역할·이미지 크기·해시를 넣어 복구 시 다른 조건을 섞지 않게 한다. 기존 후보·응답 파일과 제품 검색 경로는 그대로 유지한다.

이번 문서는 실험 설계이며 새 추론·API 호출·제품 변경을 포함하지 않는다. 대상 crop, LRCN 후보 재선정, 새 추적 모델, 독립 신규 영상 평가를 동시에 추가하지 않는다. 원본 관찰이 개선돼도 대상 식별이 주요 실패로 남으면 3단계 결과 작성 후 crop 전달만 바꾸는 다음 설계를 만든다. 운영 채택을 고려할 수준이 되면 이 개발 영상과 분리된 추가 영상으로 검증을 설계한다.
