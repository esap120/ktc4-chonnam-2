# 실험 B — Retrieval Coarse 사전검증: 프레임·문장 유사도로 사건 후보 찾기

작성일: 2026-10-11. 상태: **완료 — 약한 신호(Recall@3 4/11, 무작위 95백분위 3 초과 · 기준 5/11 미달)**. [#279](https://github.com/kakaotechcampus-4/ktc4-chonnam-2/issues/279) 실험 B(B1 최소 retrieval baseline)다. 로컬 RTX 3060 12GB에서만 실행하며 유료 API 호출·운영 코드 변경·모델 학습은 없다.

[VideoChat3 사전검증](videochat3-window-preflight-2026-10-10.md)과 같은 13클립·11사건·채점기를 쓴다. challenger 개방이 아니며, 결과는 #279 판단과 주간 회의 안건의 근거로만 쓴다.

## 1. 질문과 가설

**질문:** AI가 영상을 보고 판단하는 대신, 프레임과 사건 설명 문장의 유사도로 줄을 세우면(retrieval) set1 사건 위치에 무작위보다 나은 후보를 내는가?

- **H1:** 3유형 후보의 Recall@3이 같은 길이 무작위 후보의 95백분위를 넘는다.
- **H2:** 유사도 순위가 같은 후보를 무작위로 섞은 순위보다 Recall@3이 높다.

예상되는 약점도 미리 적는다. 프레임 한 장은 움직임을 담지 못한다. 위반 장면과 평범한 주행 장면은 한 장으로 보면 거의 같다. 그래서 신호가 약할 가능성이 크다.

## 2. 데이터

VideoChat3 실험과 같다.

| 용도 | 데이터 |
| --- | --- |
| 양성 | set1_g3 10클립, **11사건**(실선 7 · 중앙선 2 · 신호 2). C05 두 사건은 따로 센다 |
| 정상 | `20260620_141628`, `141956`(합법 점선 변경), `150504` — 3클립 |
| 정답 | `src/daesingo/search/video/정답지.md`의 set1_g3 구간 |

set1은 반복 사용한 개발 데이터라 held-out이 아니다.

## 3. 조건 (실행 전 고정)

| 항목 | 값 |
| --- | --- |
| 모델 | `google/siglip-so400m-patch14-384` (공개 이미지·문장 임베딩, fp16) |
| 프레임 | ffmpeg `-map 0:v:0 -vf fps=2`, 프레임 i의 시각 = i × 0.5초. 크기 조정은 모델 전처리(384²)에 맡긴다 |
| 문장 | VideoChat3 실험과 같은 3개 문구 그대로 (아래) |
| 원점수 | 이미지·문장 임베딩의 cosine 유사도 |
| 시간 평활 | 같은 유형 안에서 앞뒤 1프레임 포함 3프레임(1.5초) 이동 평균 |
| 유형 간 정규화 | 유형마다 **13클립 전체 프레임**의 평균·표준편차로 z-score. 정답을 보지 않는 값이다 |
| 후보 | 유형마다 z가 가장 높은 프레임 시각 t를 골라 **[t−2, t+2] (4초)** 구간을 만든다. 영상 끝에 걸리면 길이를 유지한 채 안쪽으로 민다. 같은 유형에서 이미 고른 구간과 겹치는 프레임은 건너뛴다. 유형당 최대 5개 |
| 순위 | 클립 안 모든 유형 후보를 z 내림차순(동점이면 시각 오름차순) |

| 유형 | 문장 |
| --- | --- |
| `SOLID_LINE_LANE_CHANGE` | a vehicle changes lanes by crossing a solid white lane line |
| `CENTER_LINE_CROSSING` | a vehicle crosses the center line into the opposite lane |
| `SIGNAL` | a vehicle drives through the intersection while the traffic light is red |

4초 후보 길이는 정답 사건 길이(1–4초)보다 약간 넓다. 길이로 Recall을 부풀리지 않도록 무작위 기준선도 같은 4초 길이로 만든다.

## 4. 채점

VideoChat3 실험의 채점기(`vc3_score.py`)의 함수를 그대로 가져다 쓴다.

- **적중:** 정답 유형 후보이고 `candidate.start < truth.end`와 `truth.start < candidate.end`를 모두 만족. padding 없음. 경계 접촉은 비적중.
- **조건 2개**
  - **3유형 — 판단용:** 모든 클립에서 3유형 후보 전부.
  - 정답 유형 — 참고: 양성은 라벨 유형만, 정상은 실선만. 판단에 쓰지 않는다.
- **지표:** Recall@1·@3(주)·@5, 전체 후보 겹침, C47 제외 @3, 시각 오차, 정상 클립 상위 점수, 처리 시간, 피크 VRAM.
- **기준선 (각 10,000회):** 같은 길이 무작위 위치, 같은 후보의 순위 섞기.

## 5. 판단 기준 (실행 전 고정)

| 결과 | #279 해석 | 다음 행동 |
| --- | --- | --- |
| Recall@3 > 무작위 95백분위 **그리고** ≥5/11 | A — retrieval 신호 확인 | 정식 challenger 확장 검토를 주간 회의 안건으로 |
| 무작위 95백분위 초과, 5/11 미만 | 약한 신호 | 결과만 보고. CV_LANE_TRACK 결과와 함께 재논의 |
| 무작위 95백분위 이하 | 신호 부족 | 이 방식의 retrieval Coarse는 진행하지 않음 |

5/11은 VideoChat3 실험과 같은 기준이다(Flash 1유형 Coarse 겹침 회차 평균 4.7을 넘는 최소 정수). #279의 판단 D(「목표 Recall에 충분히 접근」)는 목표 Recall이 정해져 있지 않아 이번에 판정하지 않는다.

결과를 본 뒤 모델·문장·평활·정규화·후보 길이를 바꾸지 않는다. 바꾼 조건은 새 실험 ID로 기록한다.

## 6. 한계

- 프레임 단위 유사도라 움직임(선을 넘는 과정)을 직접 보지 않는다.
- 문장은 VideoChat3 실험 문구를 재사용했다. 문구 민감도는 측정하지 않는다.
- 모델 1종만 본다. 결과가 이 모델에 한정될 수 있다.
- 모델 기본 전처리가 16:9 프레임을 384×384로 늘이거나 줄여 넣는다(비율 유지·잘라내기 없음). 기본(느린) 이미지 전처리기를 썼다.
- 11사건·1회(결정적 계산)라 1–2건 차이는 우연과 구분되지 않는다. 정상 3클립은 오탐률 근거로 부족하다.

## 8. 결과 (2026-10-11 실행)

실행: 13클립 1,240프레임 × 3문장, 1회. 누락 클립 0. 프레임 추출·임베딩 합계 60.2초(모델 로드 제외, 원본 약 620초의 0.1배), 피크 VRAM 1.97GiB. 로컬 `runs/sims.jsonl`, 채점 `runs/score.json`.

| 조건 | Recall@1 | **Recall@3** | Recall@5 | 전체 후보 겹침 | C47 제외 @3 | 후보/클립 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| **3유형 — 판단용** | 3/11 | **4/11** | 6/11 | 8/11 | 4/10 | 14.2 |
| 정답 유형 — 참고 | 4/11 | 6/11 | 8/11 | 8/11 | 6/10 | 4.8 |

| 기준선 (10,000회) | 3유형 | 정답 유형 |
| --- | --- | --- |
| 무작위 위치 Recall@3 — 평균 / 95백분위 / P(≥관측) | 1.30 / 3 / **0.019** | 3.64 / 6 / 0.099 |
| 순위 섞기 Recall@3 — 평균 / 95백분위 / P(≥관측) | 1.82 / 4 / 0.084 | 5.25 / 7 / 0.43 |
| 무작위 위치 전체 후보 겹침 — 평균 / 95백분위 / P(≥관측) | 5.11 / 8 / 0.061 | 5.12 / 8 / 0.063 |

사건별 첫 적중 순위(3유형 / 정답 유형): C05 10–12s 없음/없음 · C05 20–22s 10/5 · C00 11/3 · C08 **1**/1 · C09 없음/없음 · C33 **1**/1 · C39 4/3 · C47 5/4 · C10 **1**/1 · C28 없음/없음 · C44 **2**/1. 적중 후보의 시각 오차(후보 중점과 onset 차)는 0.5–2.5초.

**판단: 약한 신호.** 판단용 3유형 Recall@3 4/11은 무작위 위치 95백분위(3)를 넘지만 5/11에 못 미친다. H1은 지지되고(P=0.019), H2는 지지되지 않는다(순위 섞기 95백분위 4와 같음). §5에 따라 **결과만 보고하고 CV_LANE_TRACK 결과와 함께 재논의한다.**

참고(조건 다름, 판단에 쓰지 않음): VideoChat3 12초 창 3유형 Recall@3 1/11. Flash Coarse 겹침 A 회차 평균 4.7/11 · B 2.3/11 · B-split 5/11. Flash는 클립당 후보가 적고(약 1.5–3개) Fine까지 거친 값이 따로 있어, 클립당 14개 후보를 낸 이번 「전체 후보 겹침 8/11」과 직접 비교하지 않는다.

관찰 (판단에 쓰지 않음):

- **적중 4건 중 2건이 신호위반이다.** C08·C33 모두 신호 문장 후보가 rank1로 맞았다. 적신호는 프레임 한 장에 보이는 대상이라 이미지 유사도가 잡기 쉬운 유형으로 보인다. 다만 적신호가 보인 장면을 찾은 것이지, 차량이 정지선을 넘은 것을 본 것은 아니다.
- **차선 유형은 유형을 구분하지 못한다.** C10·C44에서는 세 문장의 최고점이 같은 프레임(5.5초, 31.5초)에서 나왔다. 문장 내용보다 프레임 자체의 특징이 점수를 좌우한 것으로 보인다. C44 적중은 신호 후보가 rank1, 실선 후보가 rank2였다. 실선 7건 중 상위 3개 적중은 2건, 중앙선 2건은 0건이다.
- **정상 클립을 거르지 못한다.** 정상 3클립의 상위 후보 z(1.4–1.8)가 양성 클립 상위 후보 z(0.2–2.5)와 같은 범위다. retrieval은 항상 상위 K개를 내므로 존재 판단은 Fine에 남는다.
- 처리량은 Gemini Coarse·VideoChat3보다 훨씬 작다(1,240프레임 60초, 2GiB). 비용 면에서는 후보를 넓게 뽑아 다른 단계에 넘기는 앞단으로 쓸 수 있는 수준이다.

후속: 문장을 「선에 걸친 상태」로 바꾸고 4fps·정상 문장 대비를 넣은 사후 설계 [v2](retrieval-coarse-v2-2026-10-11.md)와 차선 표시 프레임 점검을 실행했다. 둘 다 신호 부족이었다.

그 밖의 후속(이 문서에서 실행하지 않음): 신호위반만 retrieval로 후보를 내고 차선 유형은 CV_LANE_TRACK에 맡기는 분업, 또는 여러 프레임을 묶는 영상 임베딩은 새 실험 ID로 따로 설계한다. 결과를 본 뒤의 변경이라 이번 판단에는 적용하지 않는다.
