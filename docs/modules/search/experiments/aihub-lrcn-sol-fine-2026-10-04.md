# AI Hub LRCN 분류 후보 + sol Fine: 15개 영상 실험

2026-10-04 · 기존 개발 영상 · 조건당 1회 · 제품 파이프라인 변경 없음

**이번 설정의 정답 구간·종류 중첩 판정은 4/13건으로, 앞선 공간 탐지 후보 + sol Fine의 2/13건보다 많았다.** 신규 8개 영상은 C08 신호 사건 1건을 확인했고, 정상 영상 3개에서 선택된 후보 7개는 모두 기각했다. 입력·출력 합계는 약 127만 토큰으로 앞선 약 196만보다 35.4% 적었다. 다만 후보 생성뿐 아니라 Fine의 검사 종류와 대상 힌트·신호 기준도 바뀌었고 각각 1회라, LRCN 자체의 우월성이나 운영 최적 구조를 입증한 비교는 아니다.

구조화 결과·후보·호출별 판정: `aihub-lrcn-sol-fine-2026-10-04-results.json` (로컬 보관). 비교 대상: [공간 탐지 후보 + sol Fine](aihub-coarse-sol-fine-2026-10-04.md), [기존 sol set1](search-v3-gpt-sol-fine720-set1-2026-10-04.md), [AI Hub 모델 단독 평가](aihub-model-video-2026-10-04.md).

## 실행 조건

1. 이전에 실제 실행한 AI Hub LRCN의 `sliding_5sec` 분류 249개를 재사용했다. 전체 시간대를 5초 구간·2.5초 간격으로 훑고 각 구간의 25프레임을 64×64 BGR/255로 입력한 결과다. 이번에 모델을 다시 추론하지 않았다. 전체 영상 25프레임 분류와 정답 구간을 이용한 `oracle_event`는 후보로 사용하지 않았다.
2. 점수 ≥0.8인 구간 중 예측 종류별 점수가 높은 비중첩 구간 최대 2개를 선택했다. 종류 순서는 SIGNAL, CENTER_LINE_CROSSING, SOLID_LINE_LANE_CHANGE이고 점수 동률이면 이른 구간을 택했다. 총 51개: 신호 15·중앙선 16·실선 20. 비용을 제한한 초기 조건이며 최적화된 기준이 아니다. LRCN에는 정상 클래스가 없고 점수는 보정된 위반 확률이 아니다.
3. 후보 생성 입력은 파일명·길이·해시와 분류 출력뿐이다. `expected`·정답 종류·정답 구간은 모델 경계에서 버린다. 선택 함수는 oracle/whole-clip 기록을 배제한다. 후보 JSON·소스 스냅샷을 고정한 뒤 정답으로 채점했다. 이미 확인한 개발 영상이므로 held-out blind benchmark는 아니다. 정답을 보고 이 실행의 기준을 바꾸지 않았다.
4. 원본 후보 앞뒤 4초를 포함하고, 원본 영상에서 4fps·최대 높이 720p 프레임을 추출했다. 360p 원본은 확대하지 않는다. LRCN은 차량 위치를 주지 않으므로 박스·추적 ID·좌표 힌트는 없다. 실제 픽셀을 보며 대상을 찾게 했으며 `match_with_hint=null`을 요구했다.
5. `gpt-5.6-sol`, reasoning `low`, 기존 p3 기본 관찰 지침·`FineResponse`를 사용했다. 분류 종류·점수는 미확정 참고 정보로 전달했다. 세 종류를 독립 검사하고 분류 힌트와 다른 종류도 선택하게 했다. 위반 없음은 `NOT_OBSERVED`, 불명확하면 `UNCERTAIN`이다. 신호는 관련 적색 신호와 그 상태의 정지선 통과가 모두 보여야 한다는 조건을 명시했다. 응답은 후보 본문에 가장 가까운 명확한 사건 한 건을 반환한다.

Fine은 전체 영상을 모두 보지 않는다. 분류 단계가 시간대 전체를 표본으로 훑고, 선택된 51개 구간만 Fine에 전달했다. 원본의 모든 프레임을 확인한 실험도 아니다. 서로 다른 분류 종류의 후보는 중첩돼도 별도 호출했다. 이번은 예산을 고정한 후보 선택 실험이며 모든 249개 구간을 Fine에 전달하는 비교군은 실행하지 않았다.

## 응답·원본 검토

- **bridge·youtube:** index 3·4는 검은 SUV의 실선 횡단을 원본 약 8초로 기록했고, index 10은 흰 세단의 횡단을 1.5–2초로 기록했다. 원본 전후 프레임에서 해당 차량과 선을 대조했다.
- **C00:** index 14·15는 흰 세단의 황색 중앙선 횡단을 원본 12.5·13.25초로 보고했다. index 13은 SIGNAL 분류 힌트를 중앙선으로 바꿨지만 횡단 시각을 8.5초로 적어 GT 10–14초 밖이다. 종류 수정 1건이라는 자동 지표는 남기되, 이 응답을 검증된 정답 사건의 종류 수정 성공이라고 해석하지 않는다.
- **C08:** index 17은 짙은색 Mercedes 왜건의 적색 상태 진행을 원본 15.25초로 보고했다. 원본 14초에는 황색, 16초에는 적색과 진행 차량이 보인다. 응답의 적색 전환 시각 14초는 이 표본과 맞지 않아 정확한 전환 시각을 확인했다고 주장하지 않는다. 사건 구간·종류 중첩 성공과 정밀 신호 시각 검증을 구분한다.
- **C33:** index 24는 촬영 차량의 감속·정지에 집중해 적색 통과 차량을 못 찾았다. index 25는 첫 프레임부터 일부 차량이 정지선 너머에 있어 통과 순간이 없다고 답했다. 원본 50·52초에는 적색과 좌측 흰 SUV가 보이지만 관련 신호와 정확한 정지선 통과는 별도 검증이 필요하다. 제공 GT는 바꾸지 않았다.
- **C39·C47·C10·C28·C44:** 해당 사건이 Fine 입력에 들어갔지만 실제 선 횡단을 없다고 답했다. C10에서는 신호 분류 힌트를 받았어도 다른 두 종류까지 검사하도록 했으나 회복하지 못했다. 어둡고 작은 차량·선과 대상 식별 문제가 남는다. 원본 사건 구간의 전후 표본을 확인했으며 새 차량 GT를 만들지는 않았다.
- **정상 영상:** 141628·141956·150504의 후보 호출은 각각 2·2·3회이며 모두 기각했다. 정상 점선 변경의 원본 프레임도 대조했다. 선택되지 않은 정상 시간대를 sol로 전수 확인한 결과는 아니다.

검토용 원본 프레임 모음은 로컬 `lrcn-fine/evidence/first-review.jpg`, `second-review.jpg`, `third-review.jpg`에 보존했다. 원본에서 얻은 표본 이미지이며 Fine에 검토 그림·정답 표시·박스를 전달하지 않았다.

## 사용량과 검증

입력 이미지 2,390장, 입력 토큰 1,243,313·출력 24,331, API 호출 지연 합계 444.409초(약 7.4분)다. 중첩 프레임을 별도 입력한 횟수까지 포함한다. 지연은 프레임 추출·기존 분류 실행을 제외한 API 호출 시간이고 실제 전체 실행 시간과 다르다. 검증된 endpoint 요율이 없어 금액은 계산하지 않았다.

원본 15개 해시, 분류 캐시·생성 소스 해시, 후보 해시, 호출 index 0–50 완결성, 실제 반환 모델 51개, 응답 시각 범위, 이미지 개수·해시 개수, 실제 프롬프트 해시 51개를 확인했다. 분류 후보에는 차량 박스·track ID가 없고 모든 응답의 match_with_hint는 null이다. 재생성 후보가 실행 후보와 같은 것도 확인했다. 원본 분류 결과와 앞선 공간 후보 결과는 덮어쓰지 않았다.

관련 테스트 10개 통과, Ruff·형식 검사 통과, LSP 오류 없음, basedpyright 오류 0개다. 기존 프레임 추출 비공개 함수 재사용 경고 1개는 남아 있다. 새 코드의 no-excuse audit는 통과했다. 기존 두 trace 스크립트의 작업 diff 해시도 유지했다.

재현은 저장소 루트에서 실행한다. 후보를 고정한 뒤 같은 파일로 Fine을 이어서 실행한다. `<SOL_ENV>`는 로컬 API 설정이며 공개 결과에는 키와 endpoint를 넣지 않았다.

```bash
uv run --extra eval-gemini --with typer --with pycocotools python -m scripts.aihub_lrcn_candidates .omc/aihub-models/run .omc/aihub-models/lrcn-fine/candidates.json
uv run --extra eval-gemini --with typer --with pycocotools python -m scripts.aihub_hybrid_fine .omc/aihub-models/lrcn-fine/candidates.json src/daesingo/search/video <SOL_ENV> .omc/aihub-models/lrcn-fine/fine.jsonl
uv run --extra eval-gemini --with typer --with pycocotools python -m scripts.aihub_lrcn_score .omc/aihub-models/lrcn-fine/candidates.json .omc/aihub-models/lrcn-fine/fine.jsonl .omc/aihub-models/run/manifest.json .omc/aihub-models/lrcn-fine/score.json
```

후보·응답 원문·실행 소스 스냅샷·QA는 로컬 `.omc/aihub-models/lrcn-fine/`에 보존했다. 새 조건은 별도 출력 경로로 실행한다. 후보 파일이 바뀌면 기존 checkpoint에 이어서 호출할 수 없다.
