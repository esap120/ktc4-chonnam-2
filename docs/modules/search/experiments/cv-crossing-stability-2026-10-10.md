# CV_LANE_TRACK v1 · UNKNOWN 교차 후보 안정화 v2

작성일: 2026-10-10. 상태: **구현·전체 재실행·출력 검수 완료, 종합 성능 개선은 미확정**.

같은 15개 영상의 5fps 3,233프레임으로 카메라 보정, 밝기 변화에 따른 reset, 불확실한 차량 접지 대리점 처리를 변경했다. 기존 후보 5개 중 화면 끝에 잘린 차량의 2개와 작은 원거리 차량의 1개가 보류되고, C00의 동일 구간을 두 추적기가 각각 제안한 2개가 유지됐다. 카메라 보정 성공은 20프레임 늘었지만 이전 차선과 연결된 관측 수는 48개 줄었다. **v2를 전체 안정성·정확도의 개선 조건으로 선정하지 않는다.**

## 입력과 변경 범위

- [이전 UNKNOWN 후보 결과](cv-crossing-candidates-2026-10-10.md)의 V1 차량 검출, L3 UFLDv2 차선 곡선, ByteTrack/BoT-SORT 원본 관측을 그대로 사용했다. 새 모델 추론·학습·다운로드·유료 API 호출은 없다.
- 차량 bbox·ID·차선·접지·교차 시각 GT가 없다. 모든 후보는 `UNKNOWN`, 차선 confidence와 후보 score는 `null`이다. 정확도·Recall@K·위반 판정·최종 모델 선정·Top-K는 평가하지 않았다.
- 변경 파일은 `crossing_data.py`, `crossing_motion.py`, `crossing_lanes.py`, `crossing_run.py` 및 관련 geometry/runner 테스트다. 실험 스크립트만 수정했으며 운영 경로에는 적용하지 않았다.
- 기존 출력과 8개 기존 crossing 소스의 해시를 보존했다. 기존 소스는 `crossing-stability-baseline-source/`에 있다. 현재 수정된 소스로 예전 규칙 파일을 읽는 것만으로는 baseline을 재현할 수 없다.

## 실행 전에 고정한 처리

1. 유사 변환 대신 full affine으로 카메라 움직임을 맞춘다. 최소 12 inlier, inlier 비율 0.5, 잔차 p95 4px, 회전 0.15rad, 이동 15% 폭 제한을 유지한다. 양의 determinant, 두 singular value 모두 0.8–1.25, inlier의 가로·세로 분포가 각각 영상의 10% 이상인 조건을 추가했다. 좌표는 원본 해상도로 환산한다. 한 장의 affine은 도로·배경의 깊이 차이를 완전히 표현하지 못한다.
2. HSV 거리 0.45 초과만으로 장면을 끊지 않는다. 위 기하 보정이 통과하고, 차량·차선 등을 제외한 배경의 warp 후 밝기 정규화 상관계수가 0.6 이상일 때만 연결한다. 대응점·기하가 부족하면 기존처럼 reset한다. 근거 없이 identity 변환을 대입하지 않는다.
3. bbox가 보호 경계에 걸리거나 너비·높이가 원본의 각각 5%보다 작으면 접지 계산을 보류한다. 경계는 각 축에서 `max(2, ceil(0.005 × 해상도))`다. 640×360에서는 가로 4px·세로 2px, 최소 bbox 32×18px이고, 1920×1080에서는 10px·6px, 96×54px이다. 검출 bbox는 그대로 기록·표시하며, 거리 관측이 없는 해당 차량·차선 상태를 지워 보류 구간을 건너뛰어 교차를 만들지 않는다.

기존 deadband, 3관측·0.4초 유지, 0.45초 관측 간격, 차선 일대일 연결과 모호성 기각, 관측 범위 밖 외삽 금지, 후보 전후 2초 창 및 병합 조건은 유지했다. 후보 수에 맞춰 임계값을 재조정하지 않았다.

기존 실패→성공은 128프레임이고, 기존 성공→실패는 109프레임이다. 여기에 기존 cut→성공 1프레임을 더해 보정 성공의 순증가가 20이다. full affine 적용으로 일부 구간을 복구했으나 모든 영상이 개선된 것은 아니다. 예를 들어 C05는 복구 13·새 실패 18, C33은 복구 11·새 실패 20이다. 연결 차선 관측은 감소하고 ID 수는 증가했으므로, 보정 성공 합계만 보고 차선 추적이 안정화됐다고 판단할 수 없다.

새 접지 보류 횟수는 ByteTrack에서 작은 bbox 8,362·경계 bbox 1,185, BoT-SORT에서 8,336·1,187이다. 두 추적기의 전체 원본 관측은 각각 16,558·16,693개로 그대로 보존됐다. bbox 보류는 관측 단위이고 거리 관측·차선별 기각은 차량×차선 단위이므로 서로 같은 분모로 계산하지 않는다. 거리 관측 감소는 더 보수적인 입력 선택 결과이며 실제 사건 누락이 줄었다는 근거가 아니다. 원거리 차량의 실제 교차도 보류될 수 있다.

전체 CLI 1회는 기존 95.79초, v2 89.58초였다. 캐시 읽기·카메라 보정·렌더링·영상 저장을 포함하며 차량/차선 추론 및 추적 시간은 제외한다. 단일 실행이므로 처리속도 우월성은 선정하지 않는다.

## 검증과 재현 근거

기준 폴더는 `.omc/aihub-models/cv-lane-track-v1-2026-10-09/`이며 아래 파일들은 로컬 실험 증거다.

- `crossing-stability-preflight-2026-10-10-v2.json`: 실행 전 8개 소스·6개 입력·기존 결과·규칙 해시와 검토 정책 고정. 규칙 SHA-256은 `da9b407de383f4df2fd808d9d59a9d6befa8ca827e9f3c747b79519ae3914919`.
- `crossing-stability-2026-10-10-v2/summary.json`, `frames.jsonl`, `raw_candidates.json`, `candidates.json`: 모든 프레임과 실제 관측·상태·후보. 입력 해시가 기존 실행 및 preflight와 모두 일치한다.
- 같은 폴더의 `artifact_audit.json`: 모든 프레임 순서·원본 bbox/검출 연결·접지 범위·외삽 금지·reset·후보 표본/시각/병합 해시 감사 통과. 전체 상태기계를 다시 재생해 동일한 2사건을 얻어 보류 관측을 건너뛰지 않음을 확인했다.
- `video_audit.json`: 전체 영상 30개(960×540)와 후보 영상 2개(원본/오버레이 1920×540), 모두 5fps이며 총 6,506출력 프레임을 끝까지 decode해 크기·개수·SHA를 확인했다.
- `baseline_comparison.json`, `review_selection.json`, `manual_qa.json`: 실행자가 이번 턴에 raster 이미지 **55장**, 구분되는 원본 **159시점**을 직접 봤다. 15영상 각각 같은 중간 6연속 프레임, 새 후보 2개×3시점 및 거리 PNG 2장, 기존 후보 5개×3시점, 기존 cut 5쌍, 각 영상의 첫 복구/첫 새 실패 26쌍이다. 모든 출력 영상을 사람이 처음부터 끝까지 재생한 것은 아니다.
- 마지막 관련 테스트 **25 passed in 13.04s**, 11개 crossing 소스/테스트 규칙 검사 위반 0, 변경된 6개 파일 LSP 오류 0. 실제 경계·작은 bbox, 비등방 카메라 변환, 좁은 대응점 분포, 색 변화 및 다른 장면, CLI 출력·중복·overwrite 거부를 포함한다.
- `.omo/evidence/crossing-stability-code-review.md`: 로컬 읽기 전용 검토 `WATCH/APPROVE`, 차단 사항 없음. bbox 테스트의 기각 이름 검증이 약하다는 LOW 사항은 실제 C33/C10 이름·무표본 감사와 전체 상태 재생으로 별도 확인했다. 리뷰의 코드 버전 연결은 `manual_qa.json`의 8개 소스 SHA에 기록했다.

고정 실행 환경은 기존 tracking-venv의 Python 3.12.2, NumPy 1.26.4, OpenCV 4.10.0.84, lap 0.5.12, ultralytics 8.4.133, Pydantic 2.13.5다. 실행 명령은 `python -m scripts.cv_lane_track_crossing_run <tracking-diagnostic> <crossing-stability-rules-2026-10-10-v2.json> <새 빈 출력 폴더>`이고, 검토 시트는 `python -m scripts.cv_lane_track_crossing_review <출력 폴더>`다. 기존 출력 덮어쓰기를 거부한다.

## 다음 실험에 남긴 판단

불확실한 bbox를 교차 근거에서 보류하는 처리는 의도대로 작동했다. 밝기 변화 연결은 일부만 복구했고 full affine 단독 적용은 차선 연결의 전체 개선을 입증하지 못했다. 다음 비교는 기존 보정과 full affine의 선택 기준·도로 영역 대응점·차선 자체의 시간 연결을 다루는 것이 먼저다. 변경마다 동일 입력에서 복구와 새 실패를 함께 보고, 이후 필요한 정답 표본으로 실제 교차 유지·누락을 확인해야 한다. 실선/점선 분류나 위반 판정으로 확대할 근거는 아직 부족하다.
