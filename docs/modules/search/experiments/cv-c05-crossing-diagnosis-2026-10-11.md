# C05 교차 후보 누락 원인 진단

작성일: 2026-10-11. 기준은 C09 수정과 원거리 실험 설정(최소 폭2.5%·높이3.5%)을 적용한15개 영상 결과다. 기존 후보7개·정답 시간대 포함4/11을 보존했다.

## 결과

**C05에서는 차량 검출 누락보다 작은 차량 판단 보류, 차량 높이에서 차선 좌표가 끊기는 문제, 터널 보정 실패에 따른 차선ID 단절이 함께 후보 생성을 막았다.** 실제 C05 전체300프레임을 CLI로 재실행해 후보0개를 재현했다. 추가 상태 전이 버그는 확인하지 못했고, 이번에는 코드·채택 규칙을 변경하지 않았다. 두 사건은 아직 복구되지 않았으며 전체 결과는4/11 그대로다.

기존 사건10–12초(onset11),20–22초(onset21)와 사용자의 이전 확인을 모두 보존했다. 첫 사건의 기록된 거리 부호 변화는12초 이후에 가까워 원본 정답 구간과 차이가 있다. 이를 이유로 정답 시간을 옮기거나 사건을 삭제하지 않았다. 기존 사건·시각을 사용자에게 다시 입력하도록 요구하지 않았다.

## 차량은 계속 검출됐다

| 구간 | 영상상 유력 차량 | 추적 상태 |
| --- | --- | --- |
| 첫 사건 | 오른쪽 차로의 검은 차량이 촬영 차량 차로 쪽으로 이동 | ByteTrack3 / BoT-SORT7,9–14초26프레임 모두 관측, 최대 간격0.2초 |
| 두 번째 사건 | 왼쪽에서 추월한 어두운 차량이 오른쪽으로 이동 | ByteTrack9는19–24초26프레임 모두 관측, BoT-SORT30→33으로 교체 |

두 번째 유력 대상은22초부터 오른쪽 화면 가장자리에 크게 나타나는 별도 검은 차량(ByteTrack12 / BoT-SORT41)과 구분했다. 이 대상 연결은 원본과 검출을 이용한 진단이며 독립적인 GT 차량ID 확정은 아니다. 첫 대상의 검출 신뢰도는 약0.718–0.842, 두 번째는 약0.714–0.867이었다.

## 첫 사건: 크기와 차선 끝부분이 먼저 끊긴다

유력 대상은 차선source slot1, ID38에 접근한다. ID38은8.4–12.6초 유지됐다. 이 선의 원본·수용 Y범위가 같아 곡선 정리 함수가 잘라낸 경우는 아니다.

| 시각 | 차량 크기 | 선ID | 기하 거리(px) | 실제 제약 |
| ---: | --- | ---: | ---: | --- |
| 11.4 | 18×13px | 38 | +4 | 마지막으로 수용된 표본 |
| 11.6 | 18×12px | 38 | +3 | 높이12<최소12.6px |
| 11.8 | 16×12px | 38 | +1 | 크기 보류; 거리도중립 |
| 12.2 | 15×12px | 38 | −0.167 | 크기 보류; 거리도중립 |
| 12.4 | 작은 차량 | 38 | 계산 불가 | 접지 대리점Y237, 현재 차선 시작Y239 |
| 12.6 | 14×12px | 38 | −2.667 | 현재 선에는Y237이 있으나 이전 보정 곡선에는 없음 |
| 12.8 | 작은 차량 | 42 | −2.333 | 보정 실패로 새 선ID |
| 13.0 | 13×12px | 45 | −2.5 | 다시 보정 실패 |

기하 거리는 기록된 bbox 아래쪽 중앙점과 현재 차선의 거리다. 크기·이전 곡선 검증에 실패한 값을 실제 수용 표본이나 후보로 취급하지 않았다. 크기 제한을 제거해도12.4초의 현재 차선 소실과12.6초의 이전 곡선 소실 때문에 유효 표본이 없고, 이후에는ID가 교체돼 같은 차량·선의 반대쪽 유지 근거가 쌓이지 않는다.

## 보정 실패의 관측값

단순히 잔차가 커서 실패한 경우만 있는 것은 아니다. 다음 시점에서는 필요한 최소12개 inlier를 충족하지 못했다.

| 시각 | 유사 변환 실패 조건 | full affine 실패 조건 |
| ---: | --- | --- |
| 12.8 | inlier수·비율 부족(비율0.435) | 같은조건 |
| 13.0 | inlier수 부족 | inlier수·비율 부족 |
| 20.0 | inlier수 부족 | inlier수 부족 |
| 20.6 | inlier수 부족(비율0.688) | 같은조건 |
| 20.8 | inlier수 부족(비율0.563) | inlier수 부족(비율0.625) |

유사/full affine 잔차p95는 위 시점에서 약1.01–1.92px였다. 다음 보정 개선은 보호 임계값을 무조건 낮추기보다 터널에서 유효한 배경 특징점을 더 확보하는 방향을 우선 검토한다. 실제 실패 record는 `critical-motion-failures.json`에 보존했다.

## 독립 조건 재생

C05 전체300프레임의 원본 추적·연결 차선으로 거리와 상태를 다시 계산했다. 아래 조건은 진단용이며 새 운영 설정으로 선택하지 않았다.

| 변경 | 후보 전 단계의 교차 event |
| --- | ---: |
| 현재 원거리 설정 | 0 |
| 크기 제한만 제거 | 0 |
| 크기 제거+중립 최소폭0.1px, 차량폭×5%는유지 | 0 |
| 상태 reset만 무시, 기존 차선ID는유지 | 0 |
| 모든 표본의 불확실성 폭을 강제로0.1px로변경 | 2 |

마지막 조건의 두 event는 같은 두 번째 구간을 두 추적기가 기록한 것이다. −0.5→+0.167px처럼 원래±2px 중립 영역 안의 부호 변화만으로 대표20.95초·확인21.4초를 만들었다. 차량폭 기반 불확실성까지 무시한 결과라서 후보 복구로 채택하지 않았다. 실제 타이어 교차나 위반 GT를 입증하지 않는다.

## 실행과 육안 검증

- 원본의C05 전체300행을 네 스트림(V1/L3/ByteTrack/BoT-SORT)에서 그대로 추출했다. 원본 줄 번호·해시·동일행 여부를 저장했다. 특정 사건 시각만 골라 실행하지 않았다.
- 실제 `cv_lane_track_crossing_run` CLI 종료0, stderr없음,300프레임·원시/병합 후보0개.
- 실행한300개 CrossingFrame이 기존15개 영상 결과의C05 record와 필드 전체가 동일했다.
- 출력 영상2개 전체decode: 각300프레임, 총600프레임, 모두960×540.
- 원본12패널과 실제 출력16패널을 직접 확인했다. 차량관측 유지, 차선 끝부분의 범위, 보정 실패 표시와ID 교체를대조했다.
- 부모 입력·코드·원본 정답 해시 보존. Python 코드·채택 설정 변경이 없어 새회귀 테스트를 추가하거나 기존 테스트를 다시 실행하지 않았다.

현재 구조의 기하 대리점 검증이며 대상GT·차선역할·실제타이어접지·사건정확도를확정하지 않았다.

## 다음 작업

1. 터널에서 더 충분한 배경 특징점을 확보해12.8/13.0/20.6/20.8초 보정이 품질 조건을 만족하는지 비교한다. 기존 성공 구간 회귀도 같이 확인한다.
2. 먼 차량 높이의 차선 좌표가1–2px 밖에서 끊기는 문제를 입력모델·끝부분 불확실성으로 분리한다. 현재·이전곡선 모두에 근거가 있어야 하며 없는 좌표를 무조건 외삽하지 않는다.
3. 위 근거 확보 후 작은 차량정책을 다시 비교한다. 첫 사건의 기하 시각과 기존구간 차이는 보존하고 시간대를 옮겨 포함 수를늘리지 않는다.

이 진단에서는 정당한 단일 상태버그 수정안이 확인되지 않았다. C05 두 건을 포함한 잔여7구간과 정상·독립 데이터 검증은 남는다.
