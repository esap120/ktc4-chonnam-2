# 원거리 차선 끝부분의 실제 이전 관측 지원

작성일: 2026-10-11. [터널 보정 개선](cv-tunnel-motion-support-2026-10-11.md)의 후속 작업이다. 같은15영상·3,233프레임과 V1/L3/두 추적기 입력, 원거리 차량 규칙을 유지했다.

## 결과

**현재 차선의 작은 상단 공백을 직전 프레임의 실제 관측으로 보완하는 경로를 구현했다.** 원본 곡선을 늘리거나 보완점을 다음 프레임의 새 관측으로 저장하지 않는다. 전체72프레임에서 두 추적기 합계235개 거리 표본을 추가했고, 기존37,438개 거리 표본과 교차 후보7개의 전체 record를 그대로 유지했다.

C05에서는21.6초 유력 대상의 거리 표본이 두 추적기에서 복구됐다. 반대쪽 유지 관측이1→2개로 이어졌지만21.8초에 근거가 끊겨 후보는 여전히0개다. 후보가 있는 기존 정답 시간대는4/11로 동일하다. 추가 표본 수는 실제 사건 적중 수나 정확도가 아니다.

추가 표본은 C05에서2개, C08에서39개, C09에서43개, C33에서10개, C39에서8개, C47에서80개, C28에서41개, C44에서12개다. 하나의 프레임에 여러 차량·차선 쌍과 두 추적기 표본이 있을 수 있다.

## 원인은 anchor 하나의 존재 판정 누락

UFLDv2 공식 decoder는 `exist_row.argmax`가 유효한 anchor만 출력한다. 높이360에서 인접 row anchor는Y236.4845·239.4254이며 정수 출력은236·239다. C05 첫 유력 선은12.2초43점·시작Y236에서12.4초42점·Y239로 바뀌고12.6초에 돌아왔다. 두 번째 선도21.4→21.6→21.8초에 같은 변화가 있었다.

공식 함수와 어댑터 사이 좌표 손실은 확인되지 않았다. 이는 단순 반올림으로 설명할 수 없는 모델의 끝부분 관측 누락이다. 현재 캐시는 raw logits를 저장하지 않아 존재 판정의 확률이나 margin은 확인할 수 없다. 원본 차선 좌표가 없는데 있다고 기록하지 않았다.

## 적용한 보호 조건

현재 곡선이 접지 대리점 높이를 포함하면 기존 계산을 그대로 사용한다. 상단 범위가 부족한 경우만 다음 조건을 모두 만족할 때 실제 이전 보정 곡선에서 같은 높이의 X를 보간한다.

1. 같은 차선ID로 유일하게 연결됐고 이전 보정 곡선이 있다. 이전 곡선 자체가 접지 높이를 실제로 포함해야 한다.
2. 접지점 공백과 두 곡선 시작점 차이가 모두 현재 첫 관측 간격 및 이미지 높이1% 이내다.360높이에서는 한 row anchor 수준의 공백만 대상이다.
3. 현재 상단5개의 관측 높이에서 이전 곡선도 좌표를 제공하고 X차이의 최대값이 기존 중립 폭·접지 jump 한계보다 작다.
4. bbox 크기·경계·중복, 차선 매칭·모션 reset·관측 gap·반대쪽3회/0.4초 유지 조건은 그대로다.

거리 표본에 `lane_geometry_source=PREVIOUS_ALIGNED_ENDPOINT`, 공백 크기, 국소 불일치를 기록한다. 중립 폭에는 국소 불일치의 최대값을 추가해 더 보수적으로 판단한다. 현재 관측 출처는 `CURRENT`다. 접지 대리점의 원래 bbox-bottom 높이를 바꾸지 않는다.

원본 `TemporalLane.points`와 `previous_aligned`를 변경하지 않는다. 지원 점이 LaneLinker의 다음 프레임 관측으로 재귀 누적되지 않는다. 하단 공백, 실제 이전 좌표 부재, 큰 공백, 국소 급변, 연결 미확정은 계속 거부한다. 지원 좌표는 현재 모델이 직접 관측한 점과 구분하며 실제 타이어 접지 GT로 취급하지 않는다.

## C05는 왜 아직 확정되지 않는가

| 시각 | 유력 대상의 상태 |
| ---: | --- |
| 21.4 | 현재 관측: d+2.50px, 중립 폭2.00px. 반대쪽 관측1개 |
| 21.6 | 실제 이전 지원: d+4.643px, 공백1px, 국소 불일치1.052px. 중립 폭3.052px, 반대쪽 관측2개 |
| 21.8 | 14×12px bbox가 크기 조건에 실패하며, 이전 곡선도 접지Y237을 포함하지 않음. 상태 보류가 아니라 해당 쌍의 근거 삭제 |
| 22.0 | 작은 bbox 제한 등으로 유효 유지 관측 없음 |

21.6초 ByteTrack9와 BoT-SORT33의 실제 bbox는 `[316,225,332,238]`, 접지 대리점은 `(324,238)`이다. 같은 선ID58의 이전 실제 관측을 사용했다. 두 추적기에서 동일하게 관측이 복구됐고,21.8초에는 후보를 만들지 않는 것을 실제 출력과 상태 trace에서 확인했다.

첫 구간은12.4초에 이전 좌표가 남아 있어도 크기 보류가 먼저 적용된다.12.6초에는 이전 곡선의 해당 높이 좌표가 없고13초 모션 reset도 남는다. 존재하지 않는 이전 좌표를 현재 좌표로 대신하거나 정답 시간대를 이동해 후보를 늘리지 않았다.

## 검증

- 실제 C0521.6초 원본 tracking/linked-lane fixture로 수정 전 `lane_y_outside`를 재현했다. 수정 후 실제 이전 X·늘어난 중립 폭·출처를 확인했다. 이전 없음, 연결 미확정, 큰 공백, 국소 jump, 이전 쪽 공백은 모두 거부한다.
- 관련44테스트 통과. 첫 검증에서 테스트 접지X 기대값을 잘못 적은1건은 원본 bbox316..332에 맞춰324로 바로잡았고 실패 로그도 보존했다. 생산 코드의 안전 결함은 확인되지 않았다.
- 변경4개 Python 파일 LSP error0. 읽기 전용 안전 검토에서 원본 보존·재귀 누적 방지·출처 및 불확실성 일관성을 확인했다.
- 실제 전체 CLI 종료0,3,233프레임·원시/병합 후보7개. 새 출처 필드를 제외한 기하·상태 입력은 직전 실제 관측을 쓰는 독립 재생과 동일했다.
- 기존 거리 표본 전체가 필드 단위로 동일하고, 모든 추가 표본의 출처가 이전 endpoint 지원으로 기록됐다. 보정·연결 차선·차량 관측 전체도 동일했다.
- 30개 출력 영상 전체decode,총6,466프레임,960×540. C05 전후16패널과 C00·C09·C10·C44 두 추적기8패널을 직접 확인했다.
- 입력·규칙·정답 해시 보존, 실제 CLI 소스 해시가 현재 코드와 일치한다.

독립 검증 데이터와 대상 차량·실제 차선 역할·접지 GT에 의한 정확도 평가는 남는다. 후보 유형은 `UNKNOWN`, 점수와 사건 precision/recall은 계산하지 않는다.

## 남은 작업

현재·이전 곡선 어느 쪽에도 좌표 근거가 없는 끝부분은 이번 지원으로 해결되지 않는다. 모델의 해당 anchor 출력과 작은 차량 정책을 별도로 검증해야 한다. 크기 제한만 없애도 C05의 이전 곡선 공백은 남으므로, 두 원인을 분리한 비교가 다음 작업이다. 반대쪽 유지 관측을2개로 낮추거나 없는 좌표를 반복 사용해 사건을 만들지 않는다. C05 두 구간을 포함한 잔여7개 정답 시간대의 후보 복구와 정상·독립 데이터 검증은 계속 남아 있다.
