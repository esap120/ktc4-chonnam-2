# 작은 차량과 이전 차선 끝부분 검증 분리

작성일: 2026-10-11. [이전 차선의 실제 좌표 지원](cv-lane-endpoint-support-2026-10-11.md)의 후속 작업이다. 동일15영상·3,233프레임의 V1/L3·두 추적기 입력을 유지하고 크기 정책과 이전 곡선 검증을2×2로 비교했다.

## 결과

**현재 차선의 실측 좌표가 있는데 이전 곡선의 작은 상단 공백 때문에 버려지는 관측을 제한적으로 검증하는 경로를 구현했다.** 작은 차량 설정과 함께 사용하면 C05 약21초에서 두 추적기의 후보가 추가된다. 대표 시각21.047초, 확정21.8초, 반대쪽3관측·0.4초 유지다. 기존 후보7개의 사건 필드는 유지했고 전체 후보는9개다.

기존 정답 시간대에 후보가 포함된 구간은4/11→5/11이다. **정답 사건 복구나 정확도5/11을 뜻하지 않는다.** 새 C05 후보는 원거리 ByteTrack9·BoT-SORT33 차량과 선58에 붙는다. 실제 출력의21.8초 오른쪽 전경에 진입한 큰 검정 차량과 후보 bbox는 다르며, 이 단계에서는 정답 사건 대상과의 동일성을 확인하지 못했다. 시간대만 일치한 후보를 정답으로 승격하지 않았다. 모든 후보는 `UNKNOWN`, 사건 precision/recall·점수는 `null`이다.

후속 [원본 궤적 대조](cv-c05-target-identity-2026-10-11.md)에서 후보 차량이17초 왼쪽에서 추월한 검정 차량부터 이어짐을 확인했다. 새 오른쪽 전경 차량과 구분하고, 이 단락의 기존 “왼쪽 전경” 표현을 바로잡았다. 정답 설명과 부합하는 시각적 근거를 추가했으나, 직접 사용자 기록과 정답의 충돌은 그대로 보존한다.

## 효과 분리

모든 조합에서 동일한 보정 결과를 재사용하고 차선 연결·상태 판정을 처음부터 재생했다. 기존 접촉 측정 함수는 변경 전 소스 snapshot을 그대로 불러온다. 정답 시간대를 입력으로 쓰거나 시각별 규칙을 적용하지 않는다.

| --- | --- | ---: | ---: | ---: |
| 기존2.5%·3.5% | 같은 높이만 | 37,673 | 7 | 4/11 |
| 작은2%·3% | 같은 높이만 | 39,025 | 7 | 4/11 |

크기 기준만 낮추거나 검증 경로만 바꾸면 C05 후보는0개다.21.8초는14×12px 차량이며,640×360영상의 기존16×12.6px 제한에 실패한다. 작은 설정은12.8×10.8px로 양의 하한을 유지한다. 이는 별도 개발 실험 설정이며 `CrossingRules` 기본 크기 기준은 변경하지 않았다. 운영 최적값이나 독립 데이터 성능은 확정하지 않았다.

최종 조합의 추가 거리 표본은2,405개다. 이 중1,053개는 현재 실측 좌표와 인접 공통 구간 검증을 사용한다. 기존37,673표본의 거리·중립 폭·좌표 등 모든 기존 필드는 그대로이고 검증 출처 필드만 추가했다. 추가 표본 수는 실제 사건 수가 아니다.

## 현재 실측값을 보존하는 검증

기존 같은 높이 검증이 가능하면 그대로 사용한다. 이전 곡선이 해당 높이를 포함하지 않을 때만 다음 조건을 모두 만족해야 한다.

1. 현재 곡선은 접촉 대리점 높이를 실제로 포함한다. 거리와 `lane_xy`는 현재 곡선에서 계산하며, 이전 높이 좌표를 생성하지 않는다.
2. 같은 차선ID로 유일하게 연결된 이전 보정 곡선과 매칭 근거가 있다. 현재·이전 곡선 각각 최소5점이 필요하다.
3. 이전 곡선의 상단과 접촉Y 사이 공백만 허용한다. 공백은 이미지 높이1%와 현재·이전 첫 관측 간격 중 가장 작은 값 이내여야 한다. 하단 공백은 거부한다.
4. 두 곡선의 실제 Y 교집합에 있는 현재 관측점5개를 비교한다. 첫 공통점은 이전 상단에서 한 관측 간격 이내여야 한다. 부족하거나 멀리 떨어진 공통점은 거부한다.
5. 5점 X차이의 최대값은 `min(deadband_px, contact jump limit)` 이하다. 평균으로 큰 이탈을 숨기지 않으며 최대 불일치를 중립 폭에 추가한다.

출력에 `lane_geometry_source=CURRENT`, `lane_previous_check=LOCAL_ENDPOINT_OVERLAP`, 이전 끝부분 공백과 국소 불일치를 기록한다. 기존 같은 높이 검증은 `SAME_HEIGHT`, 이전 관측이 없는 새 선은 `NONE`으로 구분한다. 이전 단계의 실제 이전 좌표 지원은 별도 출처 `PREVIOUS_ALIGNED_ENDPOINT`를 유지한다.

곡선 배열·LaneLinker 상태를 변경하지 않고 보완점을 재귀 저장하지 않는다. bbox 경계·중복, 모션 reset·모호한 연결, 차량·차선ID 변경, 관측 gap, 반대쪽3회/0.4초 보호는 유지한다.

## 검증

- 실제 C0521.8초 tracking/linked-lane fixture로 수정 전 `lane_contact_jump`와 거리 표본0개를 재현했다. 수정 후 실제 현재 좌표·명시적 검증 출처·불확실성 증가를 확인했다.
- 연결 미확정, 큰 공백, 두 곡선 모두 접촉Y 없음, 이전5점 미만, 공통5점 미만, 첫 공통점이 멂, 한 공통점의 jump, 하단 공백, 기존 크기 기준 및 작은 설정 아래의 폭·높이 거부를 검증했다.
- 기존 `previous_gap` 사례는 이전 좌표 지원 함수의 거부를 유지하면서 현재 실측과 국소 검증의 명시적 허용을 함께 확인하도록 바꿨다. 큰 gap 등 거부 경계를 새 테스트로 잠갔다.
- 관련56테스트 통과. 첫 negative fixture가 이전 곡선을 빈 배열로 만들어 새 선의 정상 동작을 검사한 오류는 실제 하단 전용 곡선으로 바로잡았다. 생산 코드 변경 전 실제 실패1건을 다시 확인했고 두 로그를 보존했다.
- 변경5개 Python 파일 LSP error0. 읽기 전용 안전 검토의 공통점 수·첫 공통점 거리 회귀 보완을 반영했다.
- 전체4재생각3,233프레임. 변경 전 재생은 이전 실제 CLI 기록과 동일하며, 최종 실제 CLI 종료0·3,233프레임·후보9개는 최종 재생 기록과 완전히 동일하다.
- 모든 보정·원본/연결 차선·차량 관측은 기존과 동일하다. 입력·정답 해시도 유지하고 규칙은 두 크기 비율만 변경했다. 실제 CLI 소스 해시가 현재 코드와 일치한다.
- 출력30영상 전체decode,총6,466프레임·960×540. C05 전후16패널과 기존 C00·C09·C10·C44 두 추적기8패널을 직접 확인했다. 새 후보가 원거리 차량에 붙는다는 제한도 기록했다.
