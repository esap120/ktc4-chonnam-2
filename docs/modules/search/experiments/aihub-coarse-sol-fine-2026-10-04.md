# AI Hub Coarse 후보 + sol Fine: 15개 영상 실험

2026-10-04 · 개발 영상 진단 · 조건당 1회 · 제품 파이프라인 변경 없음

**전체 영상에서 후보를 만들고 sol로 재확인했지만, 새 영상의 최종 검출 개선은 확인하지 못했다.** 정답 유형의 후보 본문은 13건 중 7건과 겹쳤고, 앞뒤 4초를 포함한 Fine 입력은 10건을 포함했다. Fine이 정답 구간·유형에 맞게 `OBSERVED`를 낸 사건은 2건이다. 신규 8개 영상은 모두 미검출이었다. 정상 영상 3개는 모두 기각했다. 다른 차량을 대상으로 답하거나 녹색 신호 주행을 신호위반으로 답하는 실패를 확인했다.

수치·후보·호출별 구조화 기록: `aihub-coarse-sol-fine-2026-10-04-results.json` (로컬 보관). 직전 모델 단독 평가: [AI Hub 모델 9종](aihub-model-video-2026-10-04.md). 기존 sol 비교: [set1 10개 영상](search-v3-gpt-sol-fine720-set1-2026-10-04.md).

## 실행 구조

1. 이미 실행한 AI Hub 모델의 전체 영상 1fps 예측을 재사용했다. `yolo_signal`의 차량·적색 신호, `mask_lane`의 백색 선, `mask_center`의 황색 선, `mask_stop`의 정지선만 사용했다. 이번 실험에서 공간 모델을 다시 추론하거나 1fps보다 촘촘히 실행하지 않았다.
2. 차량을 IoU로 연결하고, 움직이는 차량의 하단 중앙 주변에 해당 선 마스크가 있는 시각을 후보로 삼았다. 신호 후보에는 같은 프레임의 적색 신호 존재도 요구했다. 이는 위험 가능성에 대한 휴리스틱이며 선 횡단·관련 신호 연결을 확정하는 알고리즘은 아니다.
3. 후보를 8초 구간, 4초 시작 격자로 묶고 유형마다 점수가 높은 비중첩 구간 최대 2개를 선택했다. 모든 영상에 실선·중앙선·신호의 세 유형을 동일하게 검사했다. 유형당 제한은 비용을 위한 초기 실험 조건이지 검증된 최적 설정이 아니다.
4. 각 후보 앞뒤 4초를 붙이고 원본에서 4fps, 최대 높이 720p 이미지를 추출했다. 원본이 360p면 확대하지 않았다. 동일 구간이라도 유형이 다르면 별도 호출했다.
5. `gpt-5.6-sol`, reasoning `low`, 기존 p3 Fine 프롬프트와 `FineResponse`를 사용했다. 자동 탐지 차량의 후보 시각·화면 좌표를 `target_hint`에 넣었다. 원본 이미지만 전달했으며 정답 유형·구간·수작업 차량 힌트는 넣지 않았다. 프레임 순서·4fps·후보 오류 가능성에 대한 안내를 추가했다.

Coarse 조건은 채점 전에 고정했다: 차량 confidence ≥0.4, 선·적색 신호 ≥0.25, 차량 연결 IoU ≥0.2, 최대 간격 2.1초, 횡이동 ≥차량 폭의 0.15배. 신호는 횡·종방향 이동 크기를 사용했다. 지면 접점 주변 범위는 가로 `max(12px, 차량폭/2)`, 세로 `max(6px, 영상높이/60)`이다. LRCN은 정상 클래스가 없으므로 사용하지 않았다.

후보 생성 함수에는 파일명·길이·영상 해시와 모델 출력만 전달했다. 캐시 manifest에 있는 정답 필드는 `ClipInput` 경계에서 버린다. 후보를 저장·해시 고정한 뒤에만 정답을 읽어 채점했다. 이번 개발 영상은 앞선 작업에서 이미 확인했으므로 학습·튜닝과 분리된 blind test라는 뜻은 아니다. 정답을 본 뒤 이 실행의 임계값이나 후보를 고치지 않았다.

## 기존 sol과의 비교

같은 set1 10개 영상·사건 11건으로 제한하면 이번 후보 본문은 **5/11**, Fine 입력은 **8/11**, 정답 유형·본문 중첩 최종 판정은 **1/11**이다. 성공은 기존과 같은 `YT_0002_C00`이다. 기존 sol은 3회 각각 1/11이었으므로 **같은 영상의 최종 검출 개선은 나타나지 않았다.** 신규 8개도 기존 3회와 이번 1회 모두 0건이다.

이번 후보 본문 시간 포함은 기존 sol의 33 사건-회차 중 4건보다 높다. 그러나 후보 수가 많고, 모든 유형을 검사하며, 시간 포함이 정확한 차량 선택을 뜻하지 않는다. 이번은 1회, 기존은 3회다. Fine 대상 힌트와 입력 안내도 달라 Coarse 교체의 효과만 분리한 통제 실험이 아니다. 우월성이나 일반 성능으로 결론 내릴 수 없다.

## 확인한 실패

- **정상 배제:** `141628`, `141956`, `150504`는 각각 4·3·4개 후보를 sol이 모두 기각했다. `141956`에서는 점선 존재를 근거로 기록했다. 다만 모든 호출이 실제 합법 변경 차량을 정확하게 추적했다는 뜻은 아니다.
- **신호 판단 모순:** 호출 index 42, `C33` 0–16초에서 녹색 신호 `PRESENT`, 적색 `ABSENT`를 기록하고도 신호위반 `OBSERVED`를 냈다. 근거의 정지선 통과 시각은 원본 3.75초로 정답 50–52초와 다르다. 원본 5·7초 프레임에서도 녹색이 보인다. 양성 영상의 다른 정상 구간에서 발생한 오판이라 정상 영상 3개의 오탐 통계에는 잡히지 않는다.
- **대상 연결 오류:** 호출 index 43, `C39` 49초 자동 박스는 흰색 소형 승합차에 놓였는데 Fine은 짙은 회색 SUV라고 답하고 `match_with_hint=True`를 냈다. 화면 좌표 텍스트와 자기 보고만으로 대상 연결이 보장되지 않는다.
- **유형 중복 오판:** `C00` 중앙선 사건을 호출 index 22는 실선 진로변경으로도 `OBSERVED` 처리했다. 정답 중앙선 판정 index 24와 분리했다.
- **Fine 호출 간 모순:** `C44`의 같은 구간·같은 차량 힌트를 실선 호출 index 59는 횡단 없음, 중앙선 호출 index 61은 백색 차로 구분선 횡단 있음으로 적었다. 같은 원본 관찰도 요청 유형에 따라 흔들린다.
- **선종류 문제:** `C10`은 정답 사건 구간을 포함하고 대상의 차로 변경도 기록했지만, Fine이 점선으로 판단해 기각했다. 원본의 작은 차량·선, 정답지의 미기록 선 형태를 추가 검증해야 한다. 이 실험에서는 제공 정답을 수정하지 않았다.
- **후보 선택 누락:** `C05` 첫 사건, `C09`, `C47`은 해당 유형의 Fine 입력에도 포함되지 않았다. 1fps, 단순 추적, 유형당 상위 2개 제한으로 짧거나 덜 두드러진 사건을 놓칠 수 있다.

원본 프레임 검토 산출물은 `.omc/aihub-models/hybrid/evidence/manual-review.jpg`, 자동 대상 박스와 이후 프레임 대조는 `target-review.jpg`다. 박스 그림은 검토용으로 실행 후 만들었으며 Fine에는 전달하지 않았다. 정지 프레임 검토와 응답 비교이며 모든 사건의 차량·시간 GT를 새로 확정한 작업은 아니다.

## 호출량·비용

전체 Fine 입력은 **3,490프레임**, 입력 토큰 **1,920,752**, 출력 토큰 **41,585**다. 순차 호출 지연 합계는 **738.251초**, 평균 약 **11.7초/호출**이며 프레임 추출·기존 공간 모델 실행 시간은 제외한다. 중첩 구간과 서로 다른 유형의 중복 호출도 각각 계산했다. 현재 구조는 호출량 절감에 성공했다고 볼 수 없다. 검증된 endpoint 요율을 얻지 못해 금액은 계산하지 않았다.

기존 set1과 같은 10개 영상에서는 Fine 45회, 입력 998,986·출력 29,866로 총 1,028,852토큰이었다. 기존 sol의 회차 평균 총 497,569토큰보다 약 2.1배다. 검사 유형·후보 수·대상 힌트가 달라 동일 조건의 가격 비교는 아니지만, 이번 설정의 최종 검출은 같고 토큰 사용량은 더 많았다.

## 다음 판단

AI Hub 탐지를 후보 보강에 쓰는 가능성은 남아 있지만, **현재 조합을 가장 좋은 운영 구조로 채택할 근거는 없다.** 먼저 다음을 별도 조건으로 비교해야 한다.

1. 대상 박스·대표 crop·전후 궤적을 함께 전달하고 Fine이 해당 차량을 실제로 확인하는지 검증한다. 시각 구간만 맞는 후보와 위반 차량까지 맞는 후보를 구분해야 한다.
2. 신호 Fine에서 관련 신호의 적색 상태와 정지선 통과의 시간 관계를 필수 증거로 검증한다. 녹색·적색 부재를 적고도 위반이라고 하는 응답을 자동 확정하지 않는다.
3. 후보 없는 구간이나 낮은 순위 후보를 일정 예산으로 검사하는 비교군을 둔다. 실제 시범 입력이 1fps여서 촘촘한 추적이 개선되는지는 아직 모른다.
4. 동일 영상·동일 유형 범위·동일 Fine 조건·동일 반복 수로 기존 Coarse와 AI Hub 보강의 비용 대비 미검출·오탐을 비교한다.

## 재현·검증

코드: `scripts/aihub_hybrid_candidates.py`, `scripts/aihub_hybrid_fine.py`, `scripts/aihub_hybrid_score.py`. 제품 모듈은 수정하지 않았다. 원본 가중치와 영상도 그대로다. API 연결은 이전 실험 기록에서 복구하고 실제 반환 모델을 확인했다. 키·endpoint 원문·Fine 응답 원문은 공개 결과 JSON에 넣지 않았다.

기존 AI Hub 환경과 프로젝트 환경에서 저장소 루트 기준:

```bash
python -m scripts.aihub_hybrid_candidates .omc/aihub-models/run .omc/aihub-models/hybrid/candidates.json
uv run --extra eval-gemini --extra test --with pycocotools --with typer python -m scripts.aihub_hybrid_fine .omc/aihub-models/hybrid/candidates.json src/daesingo/search/video <SOL_ENV> .omc/aihub-models/hybrid/fine.jsonl
uv run --extra eval-gemini --extra test --with pycocotools --with typer python -m scripts.aihub_hybrid_score .omc/aihub-models/hybrid/candidates.json .omc/aihub-models/hybrid/fine.jsonl .omc/aihub-models/run/manifest.json .omc/aihub-models/hybrid/score.json
```

기존 Fine checkpoint에 새로 생성한 후보 파일을 섞지 않는다. 생성 코드의 해시가 바뀌면 후보 파일 해시도 바뀌어 이어서 실행하는 것을 거절한다. 새 조건은 별도 후보 파일·출력으로 실행한다.

후보·캐시 예측·원본 영상 15개의 해시를 확인했고, 타입 수정 후 재생성한 후보 63개가 실행에 사용한 후보와 완전히 같은 것을 확인했다. 실행 당시 소스 스냅샷은 로컬 `hybrid/frozen-generator.py`, `frozen-fine-runner.py`에 보존했다. 최종 정리 코드의 소스 해시 차이는 후보 내용 변경이 아니다.

검증: 후보 추적·경계·다중 사건 채점·시각 오류 배제 및 기존 정답 파싱 테스트 8개 통과. Ruff 검사 통과, basedpyright 오류 0개, LSP 오류 없음. 타입 검사에는 기존 실험 파일의 비공개 프레임 추출 함수를 재사용한다는 경고 1개가 있다. 모든 Fine 호출 index 0–62, 반환 모델·후보 해시·유형·시각·프레임 수의 완결성을 확인했다. `OBSERVED` 4개 중 정답 구간·유형이 맞는 것은 2개이며, 나머지 2개는 위 실패 사례로 기록했다.
